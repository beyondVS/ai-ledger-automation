# Feature Specification: Ledger Detail Edit & Delete Modal (CRUD)

**Feature Branch**: `012-ledger-details-crud`

**Created**: 2026-06-07

**Status**: Draft

**Input**: User description: "가계부 상세 레코드 수동 정정(가맹점명 변경, 오분류 카테고리 교정 등) 및 수동 삭제(CRUD) 프론트엔드 모달 다이얼로그 기능 최종 개발 및 연결."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 가계부 상세 레코드 수동 정정 모달 (Priority: P1)

로그인한 사용자가 가계부 리스트에서 특정 지출 내역의 수정 단추를 누르면, 세련된 Glassmorphism 모달 다이얼로그가 활성화되어 가맹점명 및 결제 금액, 결제 일자 등의 결제 마스터 데이터를 수동으로 수정하고 저장할 수 있어야 합니다.

**Why this priority**: AI OCR이 완벽하지 않거나 가맹점명을 잘못 판독한 경우 사용자가 수동으로 즉각 정정할 수 있어야 하므로 MVP 구축에 최우선 필수 기능입니다.

**Independent Test**: 특정 가계부의 "수정" 단추 클릭 시 모달이 팝업되고, 값을 변경한 뒤 "저장"을 클릭하면 `PUT` API 요청을 전송하고 대시보드 리스트 및 월 지출 요약 카드가 300ms 이내에 갱신되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 대시보드 지출 내역 리스트를 보고 있을 때, **When** 특정 지출 카드의 "수정" 버튼을 누르면, **Then** 해당 가계부 마스터 정보가 바인딩된 수정 모달 다이얼로그가 부드러운 애니메이션과 함께 렌더링된다.
2. **Given** 수정 모달에서 가맹점명을 빈 값으로 수정하고 "저장"을 시도할 때, **When** 저장 요청이 발생하면, **Then** 클라이언트 단의 유효성 검사 필터가 동작하여 필수 입력 항목 오류 메시지를 표시하고 API 전송을 차단한다.
3. **Given** 수정 모달에서 유효한 수정값을 입력하고 "저장"을 클릭했을 때, **When** API 전송이 성공 완료되면, **Then** 모달이 닫히며 대시보드의 실 지출액 합계와 목록 카드가 즉시 새로운 값으로 실시간 갱신된다.

---

### User Story 2 - 가계부 레코드 수동 삭제 및 경고 다이얼로그 (Priority: P1)

사용자가 불필요하거나 잘못 등록된 가계부 내역을 영구히 삭제할 수 있도록, 개별 목록이나 수정 모달 내에 삭제 단추를 제공하고 클릭 시 실수 방지를 위한 안전 경고 모달을 띄워 삭제를 확정합니다.

**Why this priority**: 사용자가 잘못 업로드한 영수증 내역을 관리하고 정리하기 위한 기본 CRUD 요구사항의 핵심입니다.

**Independent Test**: 특정 가계부에서 "삭제" 단추를 누르고 경고창에서 확정 시, `DELETE` API 호출 후 대시보드 목록에서 카드가 즉각 사라지고 월 누적 지출액에서 해당 금액만큼 자동 차감 갱신되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 가계부 수정 모달 또는 목록 카드 상에서 "삭제"를 클릭했을 때, **When** 경고 확인 창이 활성화되면, **Then** "정말 삭제하시겠습니까?" 문구와 함께 붉은색 계열의 경고 포커스 다이얼로그가 표시된다.
2. **Given** 삭제 경고 창에서 "취소"를 선택하면, **When** 모달이 닫히면, **Then** 해당 가계부 데이터는 삭제되지 않고 그대로 리스트에 유지된다.
3. **Given** 삭제 경고 창에서 "확인(삭제)"을 누르면, **When** API 삭제가 성공하면, **Then** 해당 가계부 카드는 목록에서 즉시 제거되고, 월 총합산 금액 요약 카드가 비례하여 차감 계산된다.

### User Story 3 - 지출 카테고리 할당 및 오분류 교정 (Priority: P2)

로그인한 사용자는 수정 모달 내의 카테고리 선택 필드를 통해 지출 내역의 분류를 직접 지정 및 변경할 수 있어야 하며, 해당 카테고리는 가계부 테이블 및 카드에 명확히 시각화되어야 합니다. 이를 수호하기 위해 `Ledger` 모델에 `category` 필드(기본값: '미분류')를 추가 마이그레이션하여 관리합니다.

**Why this priority**: 지출 내역을 식비, 교통비, 쇼핑 등으로 범주화하여 가독성과 분석 유용성을 높이기 위함입니다.

**Independent Test**: 수정 모달 내의 카테고리 드롭다운에서 다른 카테고리를 골라 저장했을 때, 대시보드 리스트 내에 정상 변경 반영되는지 검증합니다.

**Acceptance Scenarios**:

1. **Given** 가계부 수정 모달이 켜졌을 때, **When** 카테고리 선택 영역을 클릭하면, **Then** 선택 가능한 표준 카테고리(식비, 교통비, 쇼핑 등) 목록이 노출된다.
2. **Given** 카테고리를 변경하여 저장을 마쳤을 때, **When** 목록이 새로 고침되면, **Then** 변경된 카테고리 태그가 가계부 카드 상에 정상 시각화된다.

---

### Edge Cases

- **네트워크 레이턴시/지연**: 사용자가 수정/삭제 저장 단추를 연타하는 것을 방지하기 위해 저장 실행 중 로딩 스피너 오버레이를 제공하고 버튼을 disable 처리해야 합니다.
- **비인증 권한 요청**: 타인의 가계부 ID를 URL로 불법 변조하여 `PUT` / `DELETE` API를 악의적으로 요청할 때, 백엔드 단에서 `403 Forbidden` 혹은 `404 Not Found` 처리를 리턴하여 철저히 자원을 격리하고 보호해야 합니다.
- **CASCADE 종속 삭제**: 가계부 마스터 레코드가 수동 삭제될 때, DB 외래키 제약조건에 따라 세부 품목(LedgerItem) 데이터 찌꺼기가 남지 않고 완벽하게 연쇄 CASCADE 삭제되어야 합니다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자 본인의 가계부 데이터에 대해서만 수정 및 삭제 권한을 허용해야 한다. (데이터 격리 수호)
- **FR-002**: 수정 모달 창은 가맹점명(`vendor_name`)과 결제일자(`transaction_date`) 등 필수 데이터에 대해 프론트엔드 단에서 공백 입력 방지 유효성 검사를 수행해야 한다.
- **FR-003**: 가계부 마스터가 삭제될 시, 관련 상세 품목(`LedgerItem`)들은 단일 데이터베이스 트랜잭션 원자성 세션 하에 자동으로 연쇄 삭제되어 일관성을 유지해야 한다.
- **FR-004**: 수정/삭제 성공 완료 시, 사용자가 강제 새로고침(F5)을 누르지 않아도 대시보드 가계부 목록 및 실 소비 총합 요약 수치가 300ms 이내에 즉시 갱신되어야 한다.
- **FR-005**: 백엔드 API는 RESTful 사양에 부합하도록 개별 엔드포인트를 매핑하여 제공해야 한다. (수동 수정: `PATCH /api/v1/receipts/<uuid:id>/`, 수동 삭제: `DELETE /api/v1/receipts/<uuid:id>/`)

### Key Entities

- **Ledger (가계부 마스터)**: 개별 영수증 결제 메타데이터를 저장하는 핵심 개체. `id` (UUIDv7), `vendor_name`, `transaction_date`, `total_amount`, `vat_amount`, `category` (지출 카테고리 문자열, 기본값: '미분류') 등의 속성을 가짐.
- **LedgerItem (가계부 상세 품목)**: 개별 영수증 내의 세부 개별 품목 명세를 1:N 관계로 매핑 보존하는 개체. `ledger` 외래키를 통해 부모(Ledger)와 CASCADE 연쇄 관계를 맺음.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 가계부 목록에서 "수정" 또는 "삭제" 버튼을 누른 후 모달 창이 부드럽게 표시되기까지의 시간 지연이 150ms 이내여야 한다.
- **SC-002**: 수정/삭제 API 호출 후 백엔드 DB 반영 및 프론트엔드 대시보드 리스트의 렌더링 갱신 처리가 300ms 이내에 완료되어야 한다.
- **SC-003**: 폼 유효성 검사 오류(가맹점명 누락 등) 발생 시 즉시 API 요청을 차단하고 100ms 이내에 화면에 직관적인 에러 피드백을 노출해야 한다.
- **SC-004**: 본인이 소유하지 않은 가계부 레코드에 대한 불법 수정/삭제 시도가 발생할 때 백엔드는 즉각 100% 차단하며, 프론트엔드에서 보안 경고 팝업이 출력되어야 한다.

## Assumptions

- 사용자의 브라우저 세션 정보(JWT Access Token)가 유효하며, 헤더에 자동으로 주입되어 API가 실행된다고 가정합니다.
- 수동 정정으로 가계부 최종 금액(`total_amount`)이 변경될 경우, 이에 비례해 부가세(`vat_amount`) 및 공급가액(`supply_value`) 역시 적합한 비율(예: 10% 부가세 기준 등)로 백엔드 또는 프론트엔드에서 자동 보정된다고 가정합니다.
