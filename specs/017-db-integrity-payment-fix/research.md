# Research: Database Integrity & Payment Duplicate Prevention & Category UI Fix

## 1. 결제 적재 원자성 및 트랜잭션 롤백 (Database Transaction Atomicity)

### 결정사항 (Decision)
- Django ORM의 `django.db.transaction.atomic` 컨텍스트 매니저를 사용하여 메인 가계부 레코드(`Ledger`)와 하위 품목 리스트(`LedgerItem` 배열)를 단일 데이터베이스 트랜잭션 세션 내에서 원자적으로 생성 및 수정합니다.
- 품목 데이터 적재 도중 예외가 발생하면 즉시 전체 트랜잭션을 전격 롤백(Rollback)하여 데이터 파편화(Dirty State)를 방지합니다.

### 타당성 (Rationale)
- 가계부 데이터의 강력한 일관성을 지키기 위해 메인 레코드만 성공적으로 저장되고 품목 상세 정보는 누락되는 부분 적재 오류를 완전 차단해야 합니다. 헌법 제I조(데이터 무결성 및 원자성 트랜잭션 최우선)와 직결되는 설계 요건입니다.

### 고려된 대안 (Alternatives considered)
- **세이브포인트(Savepoint) 기반 부분 롤백:** 실패한 품목 레코드만 제외하고 메인 레코드는 보존하는 방안이 검토되었으나, 상세 품목 정보가 없는 마스터 레코드는 가계부 도메인에서 무의미한 정적 정보에 불과하므로 전역 롤백을 채택했습니다.

## 2. 중복 결제 유입 감지 및 바이패스 (Duplicate Ingestion Bypass)

### 결정사항 (Decision)
- 데이터베이스 레이어의 복합 고유 제약조건(`UNIQUE (user_id, vendor_registration_number, transaction_date, total_amount)`)과 연계하여 중복 결제가 인입될 시 Django ORM의 `get_or_create` 또는 `ignore_conflicts=True`가 적용된 `bulk_create`를 사용하여 충돌을 안전하게 무시합니다.
- 중복 감지 시 에러를 던지지 않고 기존 데이터를 보존하며 성공(HTTP 200/201) 응답을 반환하여 요청을 정상 우회(Bypass)시킵니다.

### 타당성 (Rationale)
- 네트워크 순시 단절이나 클라이언트의 무작위 재시도 시 불필요한 시스템 충돌 에러 응답을 방지하여 API 서비스의 가용성과 사용자 체감 안정성을 극대화합니다.

### 고려된 대안 (Alternatives considered)
- **HTTP 409 Conflict 반환:** 중복 인입 발생 시 명시적으로 에러 응답을 전송하여 클라이언트가 처리하게 하는 대안을 검토했으나, 비동기 파이프라인(Celery 등)이나 자동 영수증 수집 웹훅 등에서 무의미한 경고 경보가 누적되는 문제가 있어 바이패스 처리로 확정하였습니다.

## 3. 1분(60초) 임계값 기반 중복 체크 알고리즘 (Time-Window Duplicate Prevention)

### 결정사항 (Decision)
- 동일한 금액 및 동일 가맹점으로 유입되는 다중 결제 건에 대해, 가맹점 발급 결제 승인번호(Approval Number)가 매핑되는 경우 승인번호의 고유성 여부를 최우선 판별합니다.
- 승인번호가 제공되지 않거나 동일할 경우에는 거래 시각(Transaction Time)의 오차 범위를 대조하여 **1분(60초) 이내**의 거래만 이중 유입에 따른 중복 결제로 판단하고, 1분을 초과하는 경우에는 개별 정상 결제 건으로 분리하여 모두 데이터베이스에 적재합니다.

### 타당성 (Rationale)
- 가맹점에서 다수 품목을 분할 결제하는 등 사용자가 의도한 정상적인 연속 결제를 중복 에러로 오작동하여 결제 내역이 가계부에서 무단 누락되는 실수를 원천 방지하기 위해 1분의 정밀 시간 임계창을 수립합니다.

### 고려된 대안 (Alternatives considered)
- **3분~5분 임계창 설정:** 대기 및 재시도 윈도우는 충분히 커버하지만, 사용자가 빠른 속도로 여러 물건을 다르게 결제할 때 오탐지가 발생할 확률이 비약적으로 증가합니다.
- **10초 이내 극단적 시간창 설정:** 통신 지연에 따른 Celery 비동기 재시도 요청이 중복으로 누적 등록될 리스크가 상존합니다. 따라서 타협점으로 60초 윈도우를 최종 선택했습니다.

## 4. FE-05-B 수정 내역 모달 카테고리 데이터 바인딩 버그 (Category Data Binding Leak)

### 결정사항 (Decision)
- 프론트엔드 수정 모달 컴포넌트 활성화 시, 거래 데이터에 할당된 기존 카테고리 식별값(ID)이 셀렉트박스의 데이터 모델(`v-model`)에 정확히 매핑되는지 마운트(Mount) 시점 바인딩 상태를 검증합니다.
- 기존 카테고리 매핑이 유실되었거나 유효하지 않은 매핑값일 경우, UI 상에서 드롭다운이 비어 보이거나 유실된 상태로 제출되는 현상을 막기 위해 **'미분류'** 카테고리 객체를 기본값으로 할당하여 렌더링을 제어합니다.
- 변경된 카테고리를 저장 및 제출할 때 폼 데이터 유효성 검사 규칙을 추가하여 카테고리 ID가 정상적으로 백엔드 페이로드에 포함되는지 유실 방지 가드를 배치합니다.

### 타당성 (Rationale)
- 초기 바인딩 시 Null/Undefined 방어 코드를 선제 배치하여 화면 렌더링 상의 구멍을 없애고 카테고리 미지정 상태의 데이터를 정상 상태로 복구할 수 있는 자연스러운 UI 흐름을 확보합니다.

### 고려된 대안 (Alternatives considered)
- **완전히 비어있는(Blank) 상태 노출:** 초기 바인딩이 누수되었을 때 공백으로 표시할 경우 사용자가 임의로 저장을 눌렀을 때 카테고리가 강제 Null 업데이트될 여지가 있어 배제하였습니다.
- **시스템 임의의 '기타' 카테고리 강제 할당:** 사용자가 카테고리 변경을 인지하기 어려우므로 수동 재선택을 적극 유도할 수 있는 '미분류' 표기를 적용하였습니다.
