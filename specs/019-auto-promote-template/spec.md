# Feature Specification: Template Promotion & Self-Healing

**Feature Branch**: `019-auto-promote-template`

**Created**: 2026-06-13

**Status**: Draft

**Input**: User description: "자율 템플릿 승인 및 자가 치유(Self-Healing) 알고리즘 고도화. 동일 정규식 규칙이 N회(예: 3회) 이상 일관되게 도출 시 `is_verified: true`로 자동 승인(Auto-Promotion)하는 로직과, 에러 발생 또는 사용자 수동 정정 시 `is_verified: false`로 강등하고 규칙을 자동 갱신(자가 치유)하는 알고리즘을 추가하여 비용 통제 시스템 완결."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Automatic Promotion of Merchant Template (Priority: P1)

미검증 상태의 가맹점 템플릿에 대해 동일한 정규식 파싱 규칙이 일정 횟수 이상 일관되게 생성되고 검증되면, 사람이 개입하지 않고도 자동으로 신뢰할 수 있는 템플릿으로 승인하는 시나리오입니다.

**Why this priority**: 관리자의 수동 검토 리소스를 획기적으로 절감하고, 반복 유입되는 가맹점에 대한 유료 LLM 비용 우회(Bypass) 적용 속도를 극대화하기 위해 가장 필수적인 핵심 가치입니다.

**Independent Test**: 미검증 가맹점 영수증을 동일 포맷으로 3회 이상 연속으로 시스템에 인입시켰을 때, 별도의 어드민 승인 없이도 해당 가맹점 템플릿이 자동으로 `is_verified: true` 상태로 승격되고 4번째 영수증부터는 LLM 호출을 우회하여 정적 파싱되는지 검증합니다.

**Acceptance Scenarios**:

1. **Given** 특정 가맹점(사업자번호 기준)의 템플릿이 존재하지 않거나 미검증(`is_verified: false`) 상태일 때, 
   **When** 동일한 레이아웃 포맷의 영수증이 3회 유입되어 매번 동일한 정규식 규칙이 성공적으로 도출되면, 
   **Then** 해당 템플릿의 일관성 카운트가 증가하여 최종적으로 `is_verified: true`로 자동 승인(Promotion)됩니다.
2. **Given** 미검증 상태의 템플릿에 대해 일관성 카운트가 진행 중일 때, 
   **When** 중간에 이전과 다른 파싱 패턴이나 상이한 정규식이 도출되면, 
   **Then** 일관성 카운트는 0으로 초기화되고 승인이 보류됩니다.

### User Story 2 - Template Demotion & Self-Healing upon Correction or Error (Priority: P2)

자동 승격되어 사용 중인 템플릿에서 파싱 에러가 발생하거나 사용자가 대시보드 상에서 파싱 데이터의 오기입을 수동으로 정정하는 경우, 해당 템플릿을 즉시 강등 처리하고 변경 사항에 맞게 규칙을 스스로 갱신(자가 치유)하는 시나리오입니다.

**Why this priority**: 가맹점의 영수증 레이아웃이 변경되었거나 초기 자동 승인에 오류가 있었을 때, 데이터 정합성을 수호하고 비용 우회 파서가 잘못된 데이터를 영속화하는 부작용을 원천 차단하기 위해 중요합니다.

**Independent Test**: 자동 승인된 템플릿으로 처리된 가계부 내역의 특정 항목(가맹점명, 금액 등)을 사용자가 수동으로 수정하거나, 파싱 도중 에러가 감지되었을 때 해당 템플릿의 검증 상태가 즉시 취소(`is_verified: false`)되며 수정본 데이터를 기준으로 새로운 정규식 파싱 규칙이 자동 재작성 및 갱신되는지 테스트합니다.

**Acceptance Scenarios**:

1. **Given** 승인된 템플릿(`is_verified: true`)을 통해 비용 우회 파싱이 정상 동작 중일 때, 
   **When** 특정 결제 건에 대해 시스템 파싱 에러가 발생하거나 사용자가 승인 정보의 특정 항목을 수동 정정하면, 
   **Then** 해당 가맹점 템플릿은 즉시 `is_verified: false`로 강등되고 바이패스 대상에서 즉각 비활성화됩니다.
2. **Given** 템플릿이 강등됨과 동시에, 
   **When** 시스템이 수동으로 정정된 최신 데이터와 오류 내역을 입력 값으로 인계받으면, 
   **Then** 이를 기반으로 기존 정규식 규칙을 파싱하여 변경된 레이아웃에 최적화된 새로운 정규식 규칙을 자동 갱신(자가 치유)합니다.

---

### Edge Cases

- **자가 치유 규칙 생성 실패**: 정정된 데이터를 바탕으로 시스템이 타당한 새로운 정규식 파싱 규칙을 도출해내지 못하는 경우, 기존 템플릿의 정규식 규칙은 안전하게 폐기되고 해당 가맹점은 관리자 수동 승인 보류(Pending) 목록으로 즉시 격리 이관되어야 합니다.
- **연속적인 수동 정정**: 자가 치유를 통해 갱신된 새로운 템플릿이 배포된 직후 또 다시 사용자 정정이 발생하는 경우, 시스템은 단순 자가 치유 루프의 무한 반복을 방지하기 위해 해당 가맹점 템플릿을 영구 차단하거나 강제로 관리자 수동 확인 필터로 이송하여 자가 치유를 중지해야 합니다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 미검증 템플릿(`is_verified: false`) 상태에서 파싱된 이력들의 정규식 패턴 일치 여부를 누적 모니터링해야 합니다.
- **FR-002**: 동일한 정규식 추출 패턴이 누적 N회(기본 임계값: 3회) 연속으로 오차 없이 일관되게 생성되는 시점에, 시스템은 관리자 수동 승인 절차 없이 해당 템플릿의 상태를 `is_verified: true`로 자동 승격시켜야 합니다.
- **FR-003**: 자동 승격된 가맹점 템플릿에 대해 비용 우회(Bypass) 파싱 중 데이터 유효성 검증 실패(에러)가 감지되거나, 사용자가 가계부 원장 대시보드 화면에서 파싱된 최종 필드 값(가맹점명, 결제금액, 세부 품목 명세 등)을 직접 정정하는 수동 정정 이벤트가 발생하면, 시스템은 이 예외를 즉각 감지해야 합니다.
- **FR-004**: 예외 감지 즉시 해당 가맹점의 템플릿 상태를 `is_verified: false`로 강등(Demotion) 조치하고, 해당 시점 이후 유입되는 영수증은 캐시 테이블 바이패스를 차단하여 전체 LLM 분석 모듈로 자동 전환해야 합니다.
- **FR-005**: 강등된 가맹점 템플릿에 대해, 시스템은 사용자의 수동 정정 데이터(Ground Truth) 및 파싱 에러 로그를 전처리 파이프라인에 입력으로 피딩하여, 변경된 레이아웃에 부합하는 정규식 파싱 템플릿 규칙을 재생성하고 템플릿에 자동 갱신(자가 치유) 적재해야 합니다.
- **FR-006**: 시스템은 템플릿의 자동 승인, 강등 및 자가 치유 수행 내역을 백그라운드에서 자율 처리하되, 최종 사용자에게는 알림을 발송하지 않고 관리자 어드민 페이지의 템플릿 이력 관리 대시보드에 실시간으로 히스토리를 로깅해야 합니다.

### Key Entities *(include if feature involves data)*

- **MerchantTemplate**:
  - 가맹점별 고유 사업자등록번호, 적재된 정규식 파싱 규칙(Regex Pattern JSON), 검증 및 승인 상태(`is_verified: boolean`), 누적 일관성 카운트(Consistency Counter), 마지막으로 감지된 사용자 정정 일시 및 갱신 히스토리 정보를 보존하는 데이터 엔티티입니다.
- **TemplateExecutionHistory**:
  - 가맹점 템플릿이 호출되어 작동한 각 트랜잭션별 실행 정보, 사용된 파싱 원본 데이터, 최종 파싱 성공 여부, 사용자 정정 이벤트 발생 여부 및 정정 전후의 필드 값 차이(Diff) 데이터를 상세히 보존하여 자가 치유 알고리즘의 입력 데이터 소스로 제공하는 모니터링 로그 엔티티입니다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 신규 가맹점 영수증이 동일 포맷으로 3회 유입되었을 때, 어드민 개입 없이 100% 자동 승인되어 4회차 입력부터 유료 LLM 호출 우회 처리가 정상 동작해야 합니다.
- **SC-002**: 자동 승인 템플릿을 통해 오작동이나 사용자 정정이 감지되었을 때, 감지 시점으로부터 5초 이내에 자동 강등이 처리되어 즉각적인 바이패스 차단 및 LLM 폴백 처리가 완료되어야 합니다.
- **SC-003**: 자가 치유 알고리즘에 의해 자동 재조정 및 갱신된 정규식 템플릿이 재적용된 이후, 해당 가맹점에 대해 유입되는 영수증의 파싱 정확도(사용자 추가 정정이 발생하지 않는 비율)가 95% 이상으로 유지되어야 합니다.

## Assumptions

- 사용자가 대시보드에서 최종적으로 수정한 데이터 값은 100% 신뢰할 수 있는 정확한 영수증 원본의 데이터(Ground Truth)로 신뢰한다는 것을 전제로 합니다.
- 가맹점의 고유 식별 수단인 10자리 사업자등록번호는 파싱의 최우선 단계에서 무손실 정밀 추출되어 가맹점 템플릿 조회 키로 작동하며, 사업자번호 자체의 오류율은 0%에 수렴한다고 가정합니다.
- 자가 치유 단계에서 갱신 규칙(정규식) 생성이 3회 이상 실패하거나 일관되지 않은 패턴이 반복 감지될 경우, 자가 치유 프로세스는 중단되고 관리자가 개입할 수 있도록 수동 승인 보류 큐로 완전 격리 이관된다고 가정합니다.
