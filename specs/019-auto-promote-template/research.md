# Research: Template Promotion & Self-Healing

이 문서는 템플릿 자동 승인 및 자가 치유 알고리즘 구현을 위해 조사된 기술적 당면 과제와 그 해결책을 정의합니다.

## Research Items & Decisions

### 1. 자율 정규식 자가 치유(Self-Healing) 알고리즘 설계

자동 승인된 템플릿의 오작동이 감지되었을 때, 수정본 데이터(Ground Truth)를 기반으로 템플릿 정규식 규칙을 동적으로 재생성하는 방안을 조사했습니다.

* **결정사항 (Decision):**
  * 사용자의 수동 정정본 데이터(JSON)와 영수증의 원시 텍스트(Raw Text)를 Gemini 멀티모달 API에 주입하여 새로운 정규식 파싱 규칙을 Pydantic 구조(Structured Output)로 재생성하도록 요청합니다.
  * 재생성된 정규식 규칙 후보군을 Celery 비동기 검증 태스크(`verify_proposed_regex_task`)로 넘겨, 기존 영수증 원시 텍스트와 정정 데이터에 적용했을 때 100% 오차 없이 파싱 결과를 내놓는지 로컬 정규식 파서로 사전 테스트합니다.
  * 사전 테스트를 통과한 경우에만 해당 템플릿의 정규식 규칙으로 갱신 반영합니다.
* **타당성 (Rationale):**
  * LLM을 사용해 복잡한 가맹점별 텍스트 레이아웃에 최적화된 유연한 정규식을 생성하는 것이 가장 정밀하며, 비동기 로컬 파서 검증 단계(Dry-Run)를 필터로 둠으로써 오작동 정규식이 템플릿에 실시간 적재되는 사고를 완벽히 예방합니다.
* **고려된 대안 (Alternatives considered):**
  * *정적 문자열 오프셋 매칭 규칙 적용:* 가맹점 텍스트에서 금액/날짜 단어 주변의 문자열 오프셋 위치를 기억하는 단순 알고리즘을 사용합니다. 그러나 가맹점 영수증 출력 장치나 포맷이 미세하게 흔들릴 경우 오작동률이 급증하여 기각했습니다.

### 2. 연속적인 수동 정정 방어 및 자가 치유 무한 루프 차단

자가 치유를 통해 갱신된 새로운 템플릿이 배포된 이후에도 사용자 정정이 반복 발생하는 예외 시나리오의 처리 방안입니다.

* **결정사항 (Decision):**
  * 자가 치유 이력을 관리하기 위해 템플릿 모델에 자가 치유 누적 횟수(`self_healing_attempts`) 필드를 추가합니다.
  * 갱신된 템플릿에 대해 30일 이내에 다시 에러나 사용자 정정이 발생하면 `self_healing_attempts` 카운트를 누적하고 다시 자가 치유를 시도합니다.
  * 만약 연속 자가 치유 시도가 3회에 도달했음에도 동일 템플릿에서 예외가 또 발생한다면, 해당 가맹점은 자가 치유 불가 대상(Blacklist)으로 플래그(`is_blacklisted: true`)를 변경하고, 바이패스 대상에서 즉시 영구 제외한 뒤 어드민 수동 검토 대기열로 강제 이송합니다.
* **타당성 (Rationale):**
  * 복잡한 가맹점 레이아웃으로 인해 LLM과 정규식 파서가 도저히 커버할 수 없는 특이 영수증 패턴이 유입되는 경우, 무한 자가 치유 루프를 차단하고 시스템 연산 예산(AI API 호출료) 낭비를 억제하기 위한 임계값 제어가 필수적입니다.
* **고려된 대안 (Alternatives considered):**
  * *임계치 없는 무제한 자가 치유:* 임계치 없이 계속 LLM을 호출해 정규식을 갱신합니다. 이 경우 레이아웃이 변덕스러운 가맹점으로 인해 클라우드 API 리소스가 비정상적으로 소모되므로 배제했습니다.

### 3. 어드민 대시보드 로깅 스키마 설계

어드민 템플릿 이력 관리 대시보드에 실시간으로 히스토리를 로깅하기 위한 데이터 정형화 방안입니다.

* **결정사항 (Decision):**
  * 기존 `TemplateExecutionHistory` 혹은 신규 로깅 테이블에 `template_id`, `execution_time`, `is_success`, `parsing_mode` (LLM vs BYPASS), `user_corrected` (boolean), `corrected_diff` (JSONB) 필드를 보존합니다.
  * 사용자가 수동 정정한 내역의 변경 전후를 `{"field": "total_amount", "before": "12000", "after": "120000"}`과 같은 Key-Value Diff 형태의 JSONB 객체로 영속화합니다.
* **타당성 (Rationale):**
  * PostgreSQL의 JSONB를 활용함으로써 테이블 스키마의 잦은 변경 없이도 정정된 세부 품목 명세 등의 다차원 데이터 Diff를 고속으로 조회 및 적재할 수 있으며, 어드민 대시보드 차트화에 최적화된 JSON 질의를 지원합니다.
* **고려된 대안 (Alternatives considered):**
  * *텍스트 기반 파일 로깅 (Logger):* Django 기본 파일 로거를 통해 파일에 기록합니다. 이 경우 어드민 대시보드 웹 UI 상에서 이력을 실시간 통계 처리 및 검색/필터링하기 위해 별도의 로그 수집/파싱기가 필요해져 아키텍처가 비대해집니다.
