# Feature Specification: 가계부 UI 고도화 2단계 및 사용자 타임존 설정 변경 기능

**Feature Branch**: `021-ledger-calendar-timezone`

**Created**: 2026-06-14

**Status**: Draft

**Input**: User description: "가계부 UI 고도화 2단계 (캘린더 뷰 및 다차원 필터링) 및 사용자 타임존 설정 변경 기능 구현. 일자별 지출 내역을 달력 화면에서 한눈에 보여주는 캘린더 뷰(Calendar View) 모드를 추가하고 상호명 검색 및 카테고리/기간/금액 대역별 다차원 검색/필터링 패널을 연동하여 검색 편의성 강화. 더불어 사용자의 고유 타임존 설정을 동적으로 갱신할 수 있는 환경설정 API 엔드포인트(PATCH /api/v1/accounts/timezone/) 및 프론트엔드 설정 탭 UI를 구축하여 영수증 결제일 타임존 정합성 파이프라인과 완벽 연동."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 일자별 지출 내역 조회를 위한 캘린더 뷰 모드 제공 (Priority: P1)

사용자는 기존의 목록 형태 보기 외에 달력(Calendar) 형태로 한 달 동안의 지출 내역을 일자별로 한눈에 조회할 수 있어야 합니다.

**Why this priority**: 가계부 사용자가 일자별 소비 패턴을 직관적으로 파악하기 위한 핵심 UX 요소로, 월별 예산 통제 및 지출 흐름 분석에 매우 높은 가치를 제공합니다.

**Independent Test**: 가계부 메인 화면에서 "캘린더 뷰" 버튼을 클릭하여 달력 형식으로 화면을 전환할 수 있으며, 각 날짜 칸에 해당 일자의 총 지출 금액과 지출 건수가 올바르게 표시되는지 확인합니다. 또한 이전 달/다음 달 이동이 정상적으로 동작하는지 검증합니다.

**Acceptance Scenarios**:

1. **Given** 가계부 메인 화면에 진입한 상태에서, **When** 사용자가 "캘린더 뷰" 토글 버튼을 클릭하면, **Then** 화면이 달력 형태로 전환되고 당월의 날짜별 총 지출액 합계와 지출 건수가 표시된다.
2. **Given** 캘린더 뷰 상태에서, **When** 사용자가 특정 일자를 클릭하면, **Then** 해당 일자에 발생한 개별 지출 내역(상호명, 카테고리, 금액)의 상세 목록이 하단 목록 영역 또는 모달 팝업으로 나타난다.
3. **Given** 캘린더 뷰 상태에서, **When** 사용자가 "이전 달" 또는 "다음 달" 이동 화살표를 클릭하면, **Then** 달력이 해당 월로 전환되고 해당 월의 지출 데이터가 동적으로 로드되어 캘린더에 표시된다.

---

### User Story 2 - 다차원 검색 및 필터링 패널 연동 (Priority: P1)

사용자는 가맹점 상호명, 카테고리, 기간, 금액 대역을 조합하여 지출 내역을 정밀하게 검색 및 필터링할 수 있어야 합니다.

**Why this priority**: 지출 내역이 누적됨에 따라 원하는 거래 건을 신속하게 찾을 수 있도록 다차원 필터를 제공함으로써 검색 편의성과 데이터 탐색성을 극대화합니다.

**Independent Test**: 필터 패널에서 상호명 입력, 카테고리 다중 선택, 기간 지정, 최소/최대 금액 범위를 설정하고 검색 버튼을 누르면 목록 뷰 및 캘린더 뷰의 노출 데이터가 필터 조건에 부합하는 항목으로만 즉시 필터링되는지 검증합니다.

**Acceptance Scenarios**:

1. **Given** 가계부 화면에서 다차원 필터 패널이 활성화된 상태에서, **When** 사용자가 상호명에 "스타벅스"를 입력하고 검색하면, **Then** 상호명에 "스타벅스"가 포함된 지출 내역만 목록 뷰와 캘린더 뷰에 반영된다.
2. **Given** 필터 패널에서 카테고리와 금액 대역(예: 10,000원 ~ 50,000원)을 지정한 상태에서, **When** 적용 버튼을 클릭하면, **Then** 해당 카테고리와 금액 범위 내의 지출 내역만 필터링되어 화면에 노출된다.
3. **Given** 활성화된 필터 조건이 존재하는 상태에서, **When** 사용자가 "필터 초기화" 버튼을 클릭하면, **Then** 모든 필터 입력값이 초기화되고 전체 지출 내역이 다시 정상적으로 로드된다.

### User Story 3 - 사용자 타임존 설정 변경 및 결제일 시간 정합성 연동 (Priority: P1)

사용자는 자신의 계정에 고유 타임존을 설정하고 동적으로 변경할 수 있어야 하며, 설정된 타임존은 영수증 분석 및 표시 시간 정합성에 반영되어야 합니다.

**Why this priority**: 글로벌 가계부 서비스 환경 및 해외 영수증/결제 처리 시, 사용자가 거주하거나 기준 구동 중인 타임존에 기반하여 결제 시간이 정확히 파악되고 가계부 화면에 일관되게 표시되어야 시간 혼선을 방지할 수 있습니다.

**Independent Test**: 사용자 환경설정 화면의 설정 탭에서 타임존을 변경(예: Asia/Seoul -> America/New_York)하고 저장한 뒤, 가계부 지출 내역의 결제일시가 변경된 타임존 오프셋 기준으로 즉시 재계산되어 표시되는지 확인하고, 영수증 업로드 시 분석된 결제일시 정보도 해당 타임존을 기준으로 저장되는지 검증합니다.

**Acceptance Scenarios**:

1. **Given** 사용자 설정 페이지의 타임존 설정 탭에서, **When** 사용자가 드롭다운에서 새로운 타임존을 선택하고 "저장"을 클릭하면, **Then** 변경된 설정이 백엔드로 전송되어 영구 저장되고 화면에 성공 메시지가 노출된다.
2. **Given** 사용자가 타임존을 "America/New_York"(UTC-4 또는 DST 적용 시 UTC-5)으로 설정한 상태에서, **When** 가계부 목록 및 캘린더를 조회하면, **Then** 저장된 타임스탬프가 뉴욕 시간 기준의 로컬 타임으로 변환되어 결제일 및 결제시각이 표시된다. (기존에 이미 저장된 지출 내역도 동적으로 변환하여 소급 적용한다.)
3. **Given** 사용자가 변경한 타임존 설정이 활성화된 상태에서, **When** 새로운 영수증(이미지/PDF 등)을 업로드하여 파이프라인을 통과시키면, **Then** 추출된 결제일시 정보는 사용자의 활성 타임존 설정을 기준으로 타임스탬프 정합성이 처리되어 DB에 연동/저장된다.

---

### Edge Cases

- **해당 월의 지출 데이터가 부재한 경우**: 캘린더 뷰에 진입 시 오류 레이아웃을 노출하는 대신, 지출 표시 금액이 0원 혹은 빈 칸인 상태의 기본 달력 판을 안정적으로 렌더링해야 합니다.
- **필터 입력값의 정합성 위반**: 금액 대역 필터에서 최소 금액이 최대 금액보다 크거나, 기간 필터에서 시작일이 종료일보다 늦은 일자로 입력된 경우, 즉시 화면에 경고 가이드를 표시하고 API 요청을 차단하여 비정상 검색 쿼리를 예방합니다.
- **비정상 타임존 정보 유입**: 환경설정 API로 전송된 타임존 문자열이 IANA 표준에 부합하지 않거나 알 수 없는 값인 경우, 백엔드는 400 Bad Request 에러를 반환하고 기본 타임존(Asia/Seoul)으로 안전하게 폴백하여 시스템 오작동을 방지합니다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 가계부 메인 화면에서 목록 뷰와 캘린더 뷰를 자유롭게 토글할 수 있는 스위처 UI를 제공해야 합니다.
- **FR-002**: 캘린더 뷰는 월 단위 격자(Grid) 구조로 날짜별 총 지출 합산 금액과 해당 날짜의 결제 내역 총 건수를 표시해야 합니다.
- **FR-003**: 다차원 필터링 패널은 상호명 검색어(부분 일치), 카테고리(체크박스/칩 형태의 다중 선택 허용 - OR 조건), 조회 기간(시작일/종료일), 최소 및 최대 금액 범위를 입력받아 검색할 수 있어야 합니다.
- **FR-004**: 캘린더 뷰 내에 표시되는 모든 통화 금액은 일관된 로컬 통화 형식으로 표시되어야 합니다. (USD 등 타 통화 결제 건이 있을 경우 기본 통화인 KRW 기준으로 환산하여 달력 내에 합산 표시한다.)
- **FR-005**: 시스템은 사용자의 고유 타임존 정보를 변경할 수 있는 사용자 환경설정(Settings) 화면 내 전용 설정 탭 UI를 제공해야 합니다.
- **FR-006**: 백엔드는 사용자 타임존 설정을 동적으로 업데이트하는 API 엔드포인트(`PATCH /api/v1/accounts/timezone/`)를 제공하고 수신된 IANA 타임존의 유효성을 검증해야 합니다.
- **FR-007**: 영수증 파싱 및 가계부 거래 적재 파이프라인은 사용자의 현재 설정된 타임존 정보를 참조하여 결제일시의 글로벌 시간대를 보정하여 영속화해야 합니다.

### Key Entities

- **UserAccount (사용자 계정)**:
  - 사용자의 프로필 및 고유 설정 정보 엔티티.
  - `timezone` 속성을 통해 사용자의 선호 타임존(예: "Asia/Seoul", "UTC")을 유지 및 관리합니다.
- **Ledger (가계부 마스터)**:
  - 가계부 지출의 기본 거래 마스터 엔티티.
  - 결제 시각(`transaction_datetime`), 상호명, 카테고리, 결제 수단, 승인 번호 등을 관리합니다.
  - 저장 시 사용자의 활성 타임존 설정에 연동되어 UTC 기준의 절대 시간으로 데이터베이스에 기록됩니다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 가계부 화면 로드 시 필터가 없는 기본 당월 지출 내역 조회 응답 및 화면 렌더링이 1초 이내에 완료되어야 합니다.
- **SC-002**: 캘린더 뷰와 목록 뷰 간의 모드 전환은 1클릭으로 수행되어야 하며, 화면 렌더링 전환 지연은 200ms 이하여야 합니다.
- **SC-003**: 다차원 필터(상호명, 카테고리, 기간, 금액 대역)를 복합 적용하여 검색 시, 데이터베이스 쿼리를 포함한 검색 렌더링 완료 속도가 95% 이상의 테스트 케이스에서 500ms 이내여야 합니다.
- **SC-004**: 사용자가 타임존을 변경하고 설정을 저장한 후, API 응답은 500ms 이내에 완료되어야 하며 페이지가 새로고침되어도 변경된 타임존이 브라우저 쿠키/세션/로컬스토리지 또는 사용자 프로필 조회를 통해 완벽히 유지되어 표시되어야 합니다.
- **SC-005**: 사용자가 타임존을 변경한 시점 이후로 기존에 등록된 지출 내역 화면 상의 시각과 새로 영수증 업로드를 통해 생성되는 지출 내역의 시각이 변경된 타임존 시간대 오프셋에 정확히 부합하게 표현되어야 합니다.

## Assumptions

- 시스템은 기본 타임존으로 'Asia/Seoul'을 채택하며, 타임존 설정 정보가 없는 사용자는 이 기본 타임존을 적용받는 것으로 가정합니다.
- 캘린더 뷰는 웹 브라우저 화면의 가로 폭에 최적화된 Grid 반응형 레이아웃을 기준으로 하며, 모바일 환경의 경우 일자별 점(Dot)이나 간략화된 뱃지로 대체될 수 있습니다.
- 카테고리 검색 필터는 백엔드에 사전에 영속화되어 정의된 카테고리 마스터 테이블의 값을 기준으로 동적으로 칩 또는 체크박스 리스트로 제공됩니다.
- 타임존 데이터베이스는 파이썬 백엔드 표준 라이브러리인 `zoneinfo`를 사용하여 검증하는 것을 전제로 합니다.
