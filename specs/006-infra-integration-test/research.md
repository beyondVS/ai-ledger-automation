# Technical Research: 1주차 인프라 중간 점검 및 로컬 통합 테스트 수행 (Infra Integration Test)

본 문서는 통합 테스트 환경에서 도커 RDBMS 물리 환경의 멱등 기동 및 [로컬 PDF -> 파싱 -> DB 트랜잭션 적재 -> FailedTask DLQ]에 이르는 E2E 데이터 흐름 무결성을 확보하기 위한 핵심 아키텍처 의사결정과 기술 연구 결과를 기록합니다.

---

## 1. Docker Compose 기반 일회성 격리 테스트 DB 가동 및 멱등 회수 전략

### **과제 및 불확실성**
통합 테스트가 구동될 때마다 기존 개발/운영용 DB 데이터를 오염시키지 않으면서 완전히 격리된 테스트 전용 DB 환경이 필요합니다. 특히, 테스트가 도중에 에러로 중단되거나 시그널 강제 종료(Ctrl+C 등)가 일어나도 남겨진 도커 컨테이너와 볼륨 리소스를 100% 깔끔하게 청소해야 합니다.

### **결결 사항 (Decision)**
통합 테스트 기동 CLI 스크립트(`scripts/run-pdf-tests`)에 쉘 레벨의 **시그널 캐치(Trap) 및 예외 처리 구문**을 완벽하게 내장하여, 정상 종료뿐만 아니라 모든 예외적인 비정상 종료 시에도 즉시 `docker compose -f docker-compose.test.yml down -v`를 자동 수행하도록 아키텍처를 강제합니다.

### **타당성 (Rationale)**
*   **리소스 고갈 예방**: 헌법 제II조(자원 점유 최적화)와 사용자 피드백(격리 소멸)을 완벽하게 만족하여, 테스트 종료 후 어떠한 쓰레기 컨테이너나 유휴 네임드 볼륨도 시스템에 잔존하지 못하게 방어합니다.
*   **실행 멱등성**: 볼륨을 완전히 삭제(`-v` 플래그)하며 소멸시키기 때문에, 다음번 기동 시 항상 빈 순수 스키마에서 마이그레이션이 실행되어 데이터 멱등성과 테스트 신뢰성이 100% 보장됩니다.

### **고려된 대안 (Alternatives)**
1.  **대안 1: 기존 개발용 DB 컨테이너 재사용 및 테이블 플러시(Flush)**
    *   *기각 사유*: 개발 중인 로컬 DB의 주요 목데이터(Mock data)가 유실될 위험이 크고, 고유 제약조건 위배 발생 시 트랜잭션이 꼬여 격리된 테스트를 보장하기 어려움.
2.  **대안 2: 컨테이너는 유지하되 테스트 DB 이름만 동적으로 랜덤 생성 (`test_xxx`)**
    *   *기각 사유*: PostgreSQL 무료 및 로컬 자원의 커넥션 풀을 낭비하고, 매 테스트마다 불필요하게 스키마 갱신 부하가 누적됨.

## 2. E2E 데이터 통합 파이프라인의 트랜잭션 범위와 FailedTask (DLQ) 저장 신뢰성

### **과제 및 불확실성**
[PDF 로드 -> fitz 텍스트 파싱 -> Django ORM 적재 -> 예외 발생 시 DLQ로 데이터 격리] 흐름에서 데이터가 데이터베이스에 커밋되기 전 혹은 커밋되는 과정에서 예외가 났을 때, 트랜잭션 원자성 범위와 DLQ 적재를 격리하는 정밀 설계가 필요합니다.

### **결정 사항 (Decision)**
*   **트랜잭션 바운더리 격리**: 무겁고 긴 파일 입출력(PDF 바이트 스트림 로드 및 PyMuPDF 파싱 연산)은 트랜잭션 **외부**에서 순수 메모리 연산으로 먼저 완수합니다. 이후 가공 완료된 데이터 페이로드를 Django ORM 데이터베이스에 삽입하는 `create_ledger_transactional` 로직 블록만 `transaction.atomic()` 단일 원자적 격리 레벨을 타고 들어가 실행합니다.
*   **FailedTask 독립 세션 커밋**: 2차 중복 PDF 유입 등으로 `IntegrityError`가 발생해 메인 트랜잭션이 전역 롤백(Rollback)된 경우, 실패 페이로드를 격리 적재하는 `FailedTask.objects.create` 연산은 롤백된 트랜잭션 세션의 영향을 받지 않도록 **새롭고 독립적인 별도의 DB 트랜잭션/세션 블록에서 분리 적재 및 즉각 커밋**되도록 구성합니다.

### **타당성 (Rationale)**
*   **DB 락 점유 극소화**: 헌법 제I조(트랜잭션 ACID)와 제II조(자원 점유 최적화)를 동시에 달성하여, 무거운 PDF 파싱 연산 도중 DB 커넥션 및 행 락(Row Lock)이 불필요하게 물려있는 시간을 0ms로 수축시킵니다.
*   **실패 복원력 (No Data Loss)**: 본 거래 적재의 실패 여부와 무관하게, 실패 로그 자체는 유실되지 않고 DLQ 데이터베이스에 영구히 영속적으로 기록되어 무손실 수집을 만족합니다.

## 3. 크로스 플랫폼 대칭 이중 자동화 검증 메커니즘

### **결정 사항 (Decision)**
로컬 인프라의 기동 및 테스트 구동은 헌법 제VI조(양대 쉘 대칭적 동등 지원)를 수호하기 위해 Windows PowerShell용 `scripts/run-pdf-tests.ps1`과 UNIX/macOS Bash용 `scripts/run-pdf-tests.sh`를 100% 동형 동등하게 배포하여 단 하나의 CLI 명령으로 전체 통합 시나리오 무결성을 입증합니다.
