# Feature Specification: Dashboard Ledger List and Detail Accordion Component

**Feature Branch**: `011-dashboard-ledger-list`

**Created**: 2026-06-07

**Status**: Approved

**Input**: User description: "대시보드 메인 가계부 리스트 뷰 및 개별 상세 내역 조회 아코디언 컴포넌트 개발. API 서버를 통해 Django ORM에서 누적 적재 데이터를 받아와 화면에 정상 렌더링 확인. (이미 10일차에 구현된 로그인 기능을 바탕으로 실제 인증된 사용자의 가계부 데이터를 호출하여 렌더링)"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 메인 가계부 리스트 조회 (Priority: P1)

로그인된 사용자는 대시보드 메인 화면에 진입했을 때, 자신이 등록한 가계부 지출 내역 리스트를 한눈에 확인할 수 있어야 합니다.

**Why this priority**: 이 기능은 사용자가 자신의 지출 내역을 확인하는 가계부 서비스의 가장 근본적인 핵심 가치입니다. 이 기능이 제공되어야 비로소 가계부로서의 유의미한 가치가 사용자에게 전달됩니다.

**Independent Test**: 로그인된 상태에서 대시보드로 진입하여, 서버에 적재된 가계부의 가맹점명, 결제 날짜, 총 결제 금액 목록이 화면에 정상적으로 렌더링되는지 확인합니다. 다른 사용자의 가계부 데이터가 노출되지 않고 완벽히 격리되는지 검증합니다.

**Acceptance Scenarios**:

1. **Given** 가계부 데이터가 존재하는 사용자로 로그인된 상태에서 대시보드 페이지에 진입했을 때, **When** 화면이 로드되면, **Then** 사용자의 가계부 마스터 리스트가 결제 날짜 최신순으로 화면에 렌더링됩니다.
2. **Given** 가계부 데이터가 전혀 존재하지 않는 사용자로 로그인된 상태에서 대시보드 페이지에 진입했을 때, **When** 화면이 로드되면, **Then** "등록된 가계부 내역이 없습니다. 첫 번째 영수증을 업로드해보세요!"라는 친절한 빈 화면(Empty State) 안내 문구가 노출됩니다.
3. **Given** 로그아웃된 비인증 사용자가 대시보드 URL에 직접 접근을 시도했을 때, **When** 접근 시도가 발생하면, **Then** 로그인 화면으로 강제 리디렉션 처리됩니다.

---

### User Story 2 - 개별 상세 내역 조회 아코디언 컴포넌트 (Priority: P1)

사용자는 가계부 리스트에서 특정 항목을 클릭(또는 터치)하여, 해당 영수증에 포함된 개별 세부 품목(상품명, 단가, 수량, 합계금액)을 펼쳐서 확인할 수 있어야 합니다.

**Why this priority**: 영수증을 단순히 총액만 저장하는 데 그치지 않고, AI Vision 분석을 통해 상세 품목 정보까지 자동화 적재하는 것이 본 제품의 주요 차별화 포인트입니다. 상세 내역 조회가 가능해야 영수증 분석 기능을 100% 활용할 수 있습니다.

**Independent Test**: 가계부 리스트의 특정 행을 클릭하여 아코디언 컴포넌트가 펼쳐지고, 그 아래에 해당 영수증에 포함된 상세 품목 목록(품목명, 단가, 수량, 합계)과 사업자등록번호 등이 오류 없이 상세 표시되는지 확인합니다. 다시 클릭하면 닫히는지 검증합니다.

**Acceptance Scenarios**:

1. **Given** 가계부 리스트가 렌더링된 화면에서, **When** 특정 가계부 항목의 행을 클릭하면, **Then** 아코디언 영역이 부드럽게 펼쳐지며 세부 품목 리스트(품목명, 단가, 수량, 합계)가 정상 노출됩니다.
2. **Given** 아코디언이 펼쳐져 상세 내역이 보이는 상태에서, **When** 동일한 항목을 다시 클릭하거나 다른 항목을 클릭하면, **Then** 기존 상세 내역 아코디언 영역이 닫힙니다.

### User Story 3 - 파싱 미완료/대기 작업 로딩 상태 표현 (Priority: P2)

사용자는 영수증을 업로드하고 아직 분석이 진행 중이거나 대기 중인 항목에 대해 메인 리스트에서 진행 상황을 파악할 수 있어야 합니다.

**Why this priority**: 영수증 업로드가 비동기로 처리되므로(3주차 고도화), 사용자가 업로드한 직후 데이터가 리스트에 즉시 반영되지 않으면 시스템 오작동으로 오인할 수 있습니다. 임시 폴링 및 대기 상태 렌더링을 프론트엔드에서 선대응하는 것이 좋은 UX의 핵심입니다.

**Independent Test**: 새로운 영수증이 업로드되어 분석 진행 중("PENDING")인 상태일 때, 리스트 뷰에서 해당 항목이 로딩 상태 UI(Spinner 또는 Shimmer)로 표시되는지 확인하고, 최종 완료("COMPLETED")가 되면 정식 데이터 행으로 교체 렌더링되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 영수증을 업로드하여 백엔드에서 비동기 분석 작업이 아직 처리 중일 때, **When** 가계부 대시보드가 로드되면, **Then** 해당 작업은 가계부 리스트의 최상단에 임시 로딩(Skeleton/Spinner) 상태 행으로 노출됩니다.
2. **Given** 임시 로딩 상태인 행에 대해 백엔드 폴링 검사 결과 분석이 성공적으로 완료("COMPLETED")되었을 때, **When** 상태가 업데이트되면, **Then** 로딩 UI가 제거되고 실제 가계부 마스터 및 세부 데이터 행으로 자연스럽게 교체 렌더링됩니다.

---

### Edge Cases

- **네트워크 오프라인 상태**: 사용자가 가계부 리스트를 보는 도중 네트워크 연결이 일시적으로 끊어지는 경우, 사용자에게 네트워크 지연/오류 경고 메시지를 노출하고 기존 캐시된 데이터를 안전하게 화면에 보존해야 합니다.
- **상세 내역(품목)이 없는 가계부**: 영수증 파싱 오류나 수동 입력 등으로 인해 상세 품목 데이터가 비어 있는 가계부의 아코디언을 펼쳤을 때, 화면이 깨지지 않고 "상세 품목 내역이 존재하지 않습니다."라는 디폴트 안내가 출력되어야 합니다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 대시보드 가계부 조회는 10일차에 구현된 **JWT 인증 토큰 기반 세션**이 유효한 로그인 사용자에게만 요청 및 노출을 허용해야 합니다.
- **FR-002**: 가계부 목록은 최근 결제한 일자(`transaction_date`) 기준 **내림차순(최신순)으로 정렬**되어 기본 렌더링되어야 합니다.
- **FR-003**: 가계부 목록의 개별 항목은 아코디언 형태로 동작하여, 사용자가 클릭 시 상세 정보(가맹점 사업자등록번호, 세부 품목명, 단가, 수량, 세액 정보 등)를 가져와 레이아웃 하단에 펼쳐 주어야 합니다.
- **FR-004**: 개별 상세 내역을 가져올 때, 가계부 리스트 API 호출 시 각 가계부 항목마다 상세 품목(items) 배열을 포함하여 함께 단번에 가져옵니다.
- **FR-005**: 리스트 상단에는 당월 총 누적 지출 금액 및 월 지출 한도 대비 달성률(%) 등 대시보드 요약 지표를 표시해야 하며, 결제일자 최신순 정렬을 기본으로 하여 당월(현재 월) 지출 내역만 먼저 리스트에 필터링해 보여줍니다.
- **FR-006**: 9일차 설계에 따른 업로드 폴링 상태 대응을 위해, 백엔드 응답의 `status` 필드가 "PENDING" 또는 "PROCESSING"인 미완료 작업은 가계부 리스트 최상단에 흐린 Shimmer(Skeleton) 형태로 배치하고, 분석 완료 시점에 실제 데이터 행으로 교체합니다.
- **FR-007**: 시스템은 데이터를 불러오는 동안 및 데이터를 불러오지 못했을 때에 대한 명확한 로딩(Skeleton) 스크린 및 에러 핸들링 UI(네트워크 불안정 안내 등)를 제공해야 합니다.

### Key Entities *(include if feature involves data)*

- **Ledger (가계부 마스터)**: 개별 결제 건에 대한 요약 정보를 보존하는 핵심 데이터 엔티티
  - 속성: ID(UUID), 가맹점명(vendor_name), 사업자등록번호(vendor_registration_number), 결제일자(transaction_date), 총액(total_amount), 공급가액(supply_value), 세액(vat_amount)
- **LedgerItem (가계부 상세 품목)**: 개별 영수증의 구체적인 세부 구매 내역을 담는 엔티티
  - 속성: ID, 가계부 ID(ledger_id - FK), 품목명(item_name), 수량(quantity), 단가(unit_price)
- **ReceiptUploadJob (업로드 작업 상태)**: 비동기 영수증 파싱 분석 작업의 라이프사이클을 추적하는 엔티티
  - 속성: ID, 사용자 ID(user_id), 상태(status - PENDING, PROCESSING, COMPLETED, FAILED), 연결된 가계부 ID(ledger_id)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 로그인에 성공한 사용자가 대시보드에 진입한 시점부터 가계부 리스트 목록 렌더링 완료까지 소요되는 총 시간(체감 로드 시간)이 1.5초 이하여야 합니다.
- **SC-002**: 가계부 목록에서 개별 아코디언 클릭 시, 상세 내역이 화면에 펼쳐지고 렌더링 완료되는 애니메이션 지연을 포함한 체감 시간이 300ms 이내여야 합니다.
- **SC-003**: 100건 이상의 가계부 데이터가 누적되어 있어도 프론트엔드 리스트 뷰에서 버벅임(FPS 저하) 없이 부드러운 스크롤링과 반응형 아코디언 펼침 연산이 유지되어야 합니다.
- **SC-004**: 비인증 사용자가 대시보드 API 엔드포인트(`api/v1/receipts/`)나 페이지로 접근 시도 시 100% 보안 격리 및 차단되고 로그인 페이지로 안정적으로 전환되어야 합니다.

## Assumptions

- **인증 토큰 유지**: 사용자는 10일차에 구현된 JWT 토큰 발급 체계(Access Token)를 브라우저 로컬 스토리지 또는 쿠키에 안정적으로 보존하고 있으며, 프론트엔드는 API 요청 시 `Authorization: Bearer <token>` 헤더를 정상적으로 동봉합니다.
- **UI 라이브러리 및 레이아웃**: 프론트엔드는 Vue 3 및 Tailwind CSS 기반의 반응형 레이아웃을 사용하며, 모바일 화면(360px)부터 데스크톱 화면(1200px 이상)까지 반응형 그리드로 지원됩니다.
- **데이터베이스 연계**: Django ORM 백엔드 API 서버는 로컬/도커 통합 인프라를 통해 PostgreSQL에 직접 연결되어 있어 실시간 쿼리 조회가 가능합니다.
