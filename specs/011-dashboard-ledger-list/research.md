# Research Report: Technical Decisions & Rationales

**Feature**: Dashboard Ledger List and Detail Accordion Component
**Date**: 2026-06-07

## Decisions & Rationales

### 1. 상세 데이터(품목 내역) 획득 방식
* **결정 사항 (Decision)**: 가계부 리스트 API 호출 시, 각 가계부 항목마다 상세 품목(`items` 배열)을 함께 포함하여 일괄 수령하도록 직렬화기(Serializer) 스펙을 확장합니다.
* **타당성 (Rationale)**: 
  * 아코디언 컴포넌트를 펼칠 때 추가적인 API 요청을 전송하지 않으므로 네트워크 레이턴시가 발생하지 않고, 즉시 렌더링(성능 목표 SC-002: 300ms 이내)을 완벽하게 만족할 수 있습니다.
  * 별도의 상세 조회 뷰 엔드포인트를 구현 및 관리할 오버헤드를 줄여 MVP 개발 생산성을 증대시킵니다.
* **고려된 대안 (Alternatives considered)**: 아코디언을 펼치는 시점에 해당 가계부 UUID를 기반으로 `api/v1/receipts/<uuid:ledger_id>/` API를 Lazy Loading으로 호출하는 방안을 고려했으나, 클릭 시 로더가 잠깐 노출되는 경험이 세련되지 못하며 백엔드 뷰를 신설해야 하는 비용 대비 비효율적이므로 기각했습니다.

---

### 2. 대시보드 리스트 정렬 및 필터링 검색 범위
* **결정 사항 (Decision)**: 결제일자(`transaction_date`) 기준 최신순 내림차순 정렬을 기본 탑재하고, 최초 조회 시 당월(현재 월) 지출 내역만 먼저 리스트에 필터링해 보여주도록 백엔드 쿼리를 제한합니다.
* **타당성 (Rationale)**: 
  * MVP 단계에서 "당월 실 소비 금액 및 월 지출 한도 대비 달성률(%)" 요약 지표와 시각적으로 동일한 기간의 목록을 매핑하여 신뢰성 높은 통계 정합성을 줍니다.
  * 불필요하게 오래된 데이터 조회를 사전에 차단하여 백엔드 쿼리 부하를 방지합니다.
* **고려된 대안 (Alternatives considered)**: 월 단위 셀렉트 필터 및 가맹점 실시간 검색 기능을 제공하는 방안도 검토되었으나, 개발 마일스톤의 집중을 위해 해당 고도화 사양은 추후 Phase 2 릴리즈로 이관하고 MVP는 단순하지만 가장 견고한 당월 기준 최신순 조회를 우선 채택했습니다.

---

### 3. 분석 진행 중 작업(PENDING/PROCESSING)의 리스트 표현
* **결정 사항 (Decision)**: 업로드 상태가 미완료된 비동기 작업(`ReceiptUploadJob`이 PENDING 또는 PROCESSING 상태인 경우)은 가계부 목록의 최상단에 흐린 Shimmer(Skeleton) 형태로 행을 선배치하여 렌더링하고 폴링이 끝나면 실데이터 행으로 부드럽게 교체합니다.
* **타당성 (Rationale)**: 
  * 사용자가 영수증을 업로드한 뒤 백그라운드에서 분석이 도는 시간 동안 페이지를 이탈하거나 혼란을 느끼지 않게 하며, 리스트 내에서 자연스럽게 영수증 분석의 순차적 흐름을 실시간성으로 체감하게 유도하여 프리미엄 PWA 사용자 경험을 줍니다.
* **고려된 대안 (Alternatives considered)**: 대시보드 상단에만 "영수증 분석 중..." 배너를 띄우고 가계부 리스트에는 렌더링하지 않는 방안도 검토되었으나, UI 완성도와 사용자 피드백 관점(비동기 적재와 E2E 연동감)에서 Shimmer 리스트 행 선배치가 훨씬 높은 가치를 주므로 기각했습니다.
