# Research: Frontend Authentication and Client-side Image Resizing

본 문서는 프론트엔드 로그인 상태 체크(인증 토큰 기반 라우터 가드) 및 모바일 클라이언트 사이드 이미지 리사이징 모듈 내장에 관한 모범 사례 및 기술 의사결정 연구 보고서입니다.

## 1. 프론트엔드 JWT 인증 토큰 보관 전략

- **결정사항 (Decision)**:
  - 사용자 로그인을 성공적으로 마친 뒤 발급받는 JWT Access Token 및 Refresh Token을 브라우저의 `LocalStorage`에 보관 및 관리합니다.
  - Vue Router 내비게이션 가드에서 라우트 이동 시마다 LocalStorage에 저장된 Access Token의 존재 및 디코딩된 만료 시점을 동기적으로 체크하여 비인가 접근을 가로챕니다.
- **타당성 (Rationale)**:
  - LocalStorage 보관 방식은 프론트엔드 애플리케이션 내에서 토큰의 수명 주기(Expiry) 및 인증 상태를 즉각 동기적으로 읽어올 수 있어 라우터 가드 구현이 매우 직관적이고 효율적입니다.
  - 페이지 새로고침 시에도 사용자 세션이 안정적으로 영구 유지되는 장점이 있습니다.
- **고려된 대안 (Alternatives considered)**:
  - **Cookie 저장 방식 (HttpOnly, Secure)**: XSS 공격에 대해 보안성이 높지만, Axios/Fetch를 사용할 때 CSRF 방어용 추가 미들웨어/토큰 로직을 설계해야 하는 복잡성이 있어, 빠른 웹 MVP 개발 일정 대비 오버헤드가 크다고 판단하여 기각하였습니다.
  - **In-Memory 저장 및 Refresh Token 활용**: 메모리에 토큰을 두어 탈취 가능성을 최소화하지만, 브라우저 탭을 새로고침할 때마다 조용히 토큰을 갱신하는 Silent Refresh API 로직이 동반되어 구현 비용이 매우 높으므로 차후 고도화 단계로 유예하였습니다.

## 2. 회원가입 시 사용자 필수 정보 수집 필드

- **결정사항 (Decision)**:
  - 회원가입 단계에서 `이메일(Email)`, `패스워드(Password)`와 함께 사용자의 `이름/닉네임(Username)`을 필수 입력값으로 요구합니다.
  - 백엔드 User 모델의 `username` 필드를 닉네임처럼 사용하도록 프론트엔드 폼에서 처리하며, `email`도 함께 입력받아 API에 전달합니다.
- **타당성 (Rationale)**:
  - 회원가입 시점에 닉네임을 수집함으로써 로그인 후 첫 화면(대시보드)에 "홍길동님 환영합니다"와 같은 개인화된 메시지를 제공하여 비즈니스 가치와 사용자 만족도를 향상시킬 수 있습니다.
- **고려된 대안 (Alternatives considered)**:
  - **이메일/패스워드만으로 가입 (최소 가입)**: 가입 허들은 낮출 수 있으나 가입 이후 필수 정보 입력을 유도하는 별도의 온보딩 스크린 또는 프로필 작성 단계를 재구현해야 하므로, 회원가입 시점에 함께 입력받는 단일 UX 흐름이 효율적입니다.

## 3. 클라이언트 사이드 이미지 리사이징 및 압축 사양

- **결정사항 (Decision)**:
  - HTML5 Canvas API를 이용하여 업로드 단추를 누르는 즉시 긴 축(Width 또는 Height) 기준 최대 `1000px`로 이미지 크기를 축소(Downsizing)합니다.
  - 축소된 Canvas 데이터를 파일 객체로 복원할 때, 포맷을 `image/jpeg`로 일괄 강제 전환하고 압축 품질(Quality)을 `0.8 (80%)`로 설정하여 최종 Blob 데이터를 서버에 송신합니다.
  - 이미 해상도 긴 축이 `1000px` 이하인 작은 이미지 파일은 화질 왜곡 및 불필요한 연산 낭비를 차단하기 위해 리사이징을 우회하고 원본 그대로 발송합니다.
- **타당성 (Rationale)**:
  - `JPEG 80%` 압축은 영수증 내의 텍스트(상호명, 사업자번호, 결제금액 등)의 시각적 선명함을 전혀 훼손하지 않으면서도 원본 대용량 사진 대비 최소 90% 이상의 전송 파일 용량을 경감해 줍니다.
  - 이는 모바일 네트워크가 열악한 환경에서도 영수증 분석 성공율을 극적으로 끌어올리는 업계의 가장 검증된 밸런스 설정입니다.
- **고려된 대안 (Alternatives considered)**:
  - **원본 파일 포맷(PNG 등)을 유지하며 해상도만 축소**: 무손실 PNG 형식은 투명도 등이 유지되지만 해상도를 줄이더라도 바이트 용량이 상당히 크게 유지되어 트래픽 90% 이상 절감이라는 비즈니스 성공 기준(SC-001) 충족이 어렵습니다.
  - **WebP 포맷 변환**: WebP는 압축 효율이 뛰어나지만 iOS 구버전 등 일부 레거시 모바일 브라우저 환경에서 Canvas를 통한 WebP 파일 렌더링/인코딩 호환성을 완벽히 보장받기 어려워 가장 범용적인 JPEG를 최종 변환 포맷으로 채택하였습니다.
