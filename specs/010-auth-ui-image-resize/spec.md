# Feature Specification: Frontend Authentication and Client-side Image Resizing

**Feature Branch**: `010-auth-ui-image-resize`

**Created**: 2026-06-05

**Status**: Draft

**Input**: User description: "프론트엔드 로그인 상태 체크(인증 토큰 기반 라우터 가드 구현) 및 실제 사용자 로그인/회원가입 UI 화면 개발. 모바일 사용자 전용 클라이언트 사이드 이미지 리사이징 모듈 내장 (HTML5 Canvas API를 이용하여 업로드 단추를 누르기 직전 1000px 규격 최적화 압축 처리 가동하여 네트워크 트래픽 절감)."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 사용자 로그인 및 회원가입 UI (Priority: P1)

사용자는 이메일과 비밀번호를 입력하여 새로운 회원 계정을 생성하고 안전하게 서비스에 로그인할 수 있는 화면 인터페이스를 제공받아야 합니다. UI는 데스크톱과 모바일 환경 모두에 최적화된 유연한 레이아웃을 제공합니다.

**Why this priority**: 서비스 내 모든 유료 기능 및 개인화 데이터를 보호하기 위한 근본적인 접근 통제 관문이며, 사용자 유입의 첫 단추입니다.

**Independent Test**: 로컬 가상 백엔드 또는 모크 서버를 대상으로 신규 계정을 등록하고 가입된 자격 증명을 사용하여 로그인 성공 및 실패 알림이 제대로 작동하는지 개별 검증이 가능합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 회원가입 화면에 있고 이메일, 비밀번호, 비밀번호 확인을 입력했을 때, **When** 가입하기 버튼을 클릭하면, **Then** 계정이 정상적으로 생성되고 로그인 화면으로 즉시 전환됩니다.
2. **Given** 사용자가 로그인 화면에 있고 가입되지 않은 이메일 주소나 일치하지 않는 패스워드를 입력했을 때, **When** 로그인 버튼을 클릭하면, **Then** 화면에 명확한 입력 정보 불일치 경고 메시지가 표시되며 로그인이 거부됩니다.

---

### User Story 2 - 인증 토큰 기반 라우터 가드 및 상태 체크 (Priority: P2)

사용자가 로그인하면 시스템은 인증 토큰을 발급받아 유지하며, 사용자가 영수증 업로드 화면 등 인증이 필수적인 보안 영역 경로에 진입을 시도할 때 클라이언트 가드가 활성화되어 미인증 사용자의 무단 침입을 차단합니다. 또한, 이미 로그인한 사용자가 로그인/회원가입 경로로 되돌아가는 것을 방지합니다.

**Why this priority**: 안전한 비즈니스 로직 처리 및 개인정보 유출 방지를 위해 권한별 라우팅을 차단하고 통제하는 핵심 보안 계층입니다.

**Independent Test**: 브라우저의 저장된 토큰이 없는 상태로 영수증 관리자 대시보드(보호된 URL)에 직접 주소 입력을 통해 진입을 시도하여 로그인 페이지로 적절히 튕겨 나가는지 테스트합니다.

**Acceptance Scenarios**:

1. **Given** 브라우저에 유효한 로그인 인증 토큰이 보관되어 있지 않을 때, **When** 보호된 내부 영수증 업로드/관리 URL로 직접 주소 접근을 시도하면, **Then** 시스템은 즉시 라우터 수준에서 접근을 차단하고 로그인 페이지로 사용자를 이동시킵니다.
2. **Given** 사용자가 정상적으로 로그인하여 유효한 인증 토큰을 보관 중일 때, **When** 뒤로가기 또는 주소창 수동 입력을 통해 로그인 및 회원가입 페이지에 접근하려 하면, **Then** 시스템은 대시보드(메인 페이지)로 사용자를 자동 리다이렉트합니다.

### User Story 3 - 모바일 사용자 전용 클라이언트 사이드 이미지 리사이징 (Priority: P3)

사용자는 모바일 웹 브라우저에서 영수증 사진을 촬영하거나 갤러리에서 고용량 이미지를 업로드할 수 있습니다. 업로드 단추를 누르는 즉시 클라이언트 내장 리사이징 엔진(HTML5 Canvas API)이 백그라운드에서 동작하여 가로/세로 중 긴 축을 1000px로 축소 및 압축한 뒤, 축소된 바이너리 파일을 서버로 전송합니다.

**Why this priority**: 모바일 네트워크 트래픽 용량을 획기적으로 줄여 업로드 성공율을 극대화하고 서버의 스토리지 및 네트워크 데이터 비용을 절감합니다.

**Independent Test**: 5MB 크기(예: 4000x3000px)의 원본 이미지 파일을 선택해 업로드 버튼을 눌렀을 때, 네트워크 탭 상에 전송되는 파일의 용량이 대폭 줄어들었으며 해상도가 1000px로 리사이징되어 도달하는지 여부를 검증할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 모바일 기기 브라우저에서 영수증 업로드 폼에 4000x3000px 용량의 원본 사진을 첨부했을 때, **When** 업로드 버튼을 클릭하면, **Then** 서버 API로 페이로드가 발송되기 전 브라우저 내 Canvas API가 작동하여 가로 1000px 세로 750px로 압축된 이미지가 최종 송신됩니다.
2. **Given** 사용자가 이미 1000px 이하(예: 800x600px)인 저해상도 이미지를 첨부했을 때, **When** 업로드 버튼을 클릭하면, **Then** Canvas API는 화질 왜곡 및 불필요한 연산을 막기 위해 업사이징(확대) 리사이징을 우회하고 원본 크기 그대로 서버에 업로드를 요청합니다.

---

### Edge Cases

- **훼손된 이미지 및 비-이미지 형식 업로드**: 이미지 형식이 아닌 훼손된 바이너리 파일이나 TXT, PDF 파일을 이미지 첨부 영역에 올리려 시도하는 경우, 리사이징 연산 전에 MIME 타입을 판단하여 명확한 오류 안내 팝업을 노출하고 동작을 안전하게 취소해야 합니다.
- **매우 열악한 모바일 단말 사양**: 단말의 메모리가 극도로 제한된 저사양 모바일 기기에서 15MB 이상의 초대형 영수증 이미지를 업로드 시 Canvas 버퍼 오버플로우나 메모리 크래시가 유발될 수 있으므로, 임계 한계를 초과하는 원본 파일에 대한 사전 용량 차단 필터가 동작해야 합니다.
- **이미지 메타데이터(EXIF) 회전 오류**: 모바일 카메라로 세로로 촬영된 사진이 Canvas 드로잉 과정에서 가로로 90도 눕는 등의 현상을 방지하기 위해, 원본 사진의 방향 메타데이터를 감지 및 반영해 올바른 정방향 리사이징이 이뤄져야 합니다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자로부터 이메일과 비밀번호를 입력받아 새로운 사용자 데이터를 적재할 수 있는 회원가입 UI와 인증을 요구하는 로그인 UI를 제공해야 합니다.
- **FR-002**: 회원가입 시, 시스템은 보안과 비즈니스 정합성을 위해 이메일, 패스워드와 함께 사용자의 이름(닉네임)을 필수적으로 수집해야 합니다.
- **FR-003**: 사용자가 로그인을 성공적으로 마쳤을 때, 시스템은 서버로부터 발급받은 인증 토큰을 브라우저의 LocalStorage 또는 SessionStorage 영역에 보존하고 관리해야 합니다.
- **FR-004**: 라우터 가드는 사용자의 라우트 이동을 실시간 가로채기(Intercept)하여, 인증 토큰 유무 및 만료 상태를 체크하고 비인가 접근인 경우 로그인 페이지로 통제하여야 합니다.
- **FR-005**: 이미지 업로드 이벤트가 발생하면 서버에 요청을 전송하기 전 클라이언트 사이드 HTML5 Canvas API를 이용하여 긴 축 기준 1000px 크기로 다운사이징하고, 파일 포맷을 JPEG로 일괄 변환하여 80%의 압축 품질(Quality)을 적용함으로써 용량을 최적화해야 합니다.
- **FR-006**: 이미지 리사이징 도중 비정상적인 버그나 연산 에러가 발생한 경우, 전체 파일 업로드를 중단하고 사용자에게 친절한 에러 다이얼로그를 표시하여 재시도를 유도해야 합니다.

### Key Entities *(include if feature involves data)*

- **UserSession (사용자 세션)**:
  - 사용자 인증 상태를 모델링하는 비영속적 개체.
  - 속성: `accessToken` (JWT 토큰), `tokenExpiry` (만료 일시), `userEmail` (접속 사용자 계정 식별자)
- **ImageUploadPayload (이미지 업로드 페이로드)**:
  - 서버로 전송되기 직전 변형된 리사이징 영수증 이미지 데이터 개체.
  - 속성: `originalFileName` (원본 파일명), `mimeType` (이미지 포맷), `compressedBlob` (축소 변환된 바이너리 데이터), `dataSize` (최종 절감된 바이트 크기)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 모바일 환경에서 5MB(5,120KB) 이상의 고용량 영수증 이미지 업로드 시, 클라이언트 사이드 압축 모듈 가동을 거쳐 최종 서버 전송 파일 크기가 500KB 이하로 감소하여 네트워크 데이터 트래픽을 90% 이상 절감해야 합니다.
- **SC-002**: 비로그인 사용자가 대시보드 등의 보안 경로 진입을 시도할 시, 프론트엔드 라우터 가드가 차단 후 로그인 페이지로 0.5초 이내에 리다이렉트 처리를 완수해야 합니다.
- **SC-003**: 사용자가 로그인/회원가입 폼을 제출하여 인증 통과 피드백을 수신하고 첫 페이지를 렌더링하기까지의 화면 응답 대기 시간이 정상 네트워크 환경에서 2초 이내여야 합니다.

## Assumptions

- 프론트엔드 애플리케이션은 토큰 기반 인증 API가 완성된 백엔드 서버와 통신할 준비가 되어 있다고 가정합니다.
- HTML5 Canvas API 및 File Reader API가 원활하게 작동되는 모던 모바일 브라우저(iOS Safari, Android Chrome 등) 환경을 타겟팅합니다.
- 사용자는 네트워크 장애 등으로 인해 전송 실패가 발생할 경우, 클라이언트의 안전한 재시도 팝업을 통해 업로드를 복구할 수 있다고 가정합니다.
