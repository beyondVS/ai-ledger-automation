# Feature Specification: PWA Integration & Mobile Camera Capture

**Feature Branch**: `024-pwa-camera-integration`

**Created**: 2026-06-16

**Status**: Draft

**Input**: User description: "PWA Manifest/Service Worker 캐시 연동 및 HTML5 Capture API 모바일 기기 카메라 연동."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 홈 화면에 가계부 앱 추가 (A2HS) 및 오프라인 접속 (Priority: P1)

사용자는 모바일 브라우저를 통해 가계부 웹 앱에 접속한 후, 브라우저가 제공하는 앱 설치 안내를 따라 홈 화면에 웹 앱 아이콘을 추가할 수 있습니다. 이후 네트워크 연결이 끊긴 오프라인 상태에서도 홈 화면의 아이콘을 터치해 실행하면 브라우저의 에러 페이지 대신 캐싱된 정적 웹 페이지 리소스들이 즉각 실행되어 앱의 기본 대시보드 구조 및 오프라인 알림 화면을 조회할 수 있습니다.

**Why this priority**: 모바일 사용자의 이탈률을 방지하고 데스크톱 및 모바일 기기를 아우르는 심리스한 PWA 웹 앱 경험을 제공하기 위한 중추적인 기반 요구사항입니다.

**Independent Test**: 기기를 비행기 모드로 전환하거나 모바일 네트워크를 차단한 상태에서, 홈 화면에 설치된 가계부 앱 아이콘을 클릭했을 때 정적 자산(CSS, JS, 메인 레이아웃 및 폰트)이 3초 이내에 로컬 캐시로부터 완전히 로드되어 렌더링되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 모바일 기기로 가계부 서비스에 최초 접속한 후 서비스 워커와 매니페스트가 성공적으로 설치되었을 때, **When** 홈 화면 추가(A2HS) 팝업이나 메뉴를 통해 앱을 설치하고 실행하면, **Then** 주소 표시줄이나 브라우저 조작계가 없는 네이티브 앱과 같은 Standalone 화면 모드로 앱이 실행된다.
2. **Given** 기기의 네트워크 연결이 물리적으로 완전히 차단된 상태에서, **When** 홈 화면의 가계부 앱 아이콘을 클릭하여 기동하면, **Then** 화면에 인터넷 연결 실패 오류 페이지 대신 캐싱된 정적 웹 자산이 즉각 로딩되어 메인 레이아웃이 화면에 출력된다.

### User Story 2 - HTML5 Capture API 기반 모바일 영수증 촬영 및 업로드 (Priority: P1)

사용자는 가계부 신규 내역 등록 화면에서 "영수증 촬영" 버튼을 선택하여 모바일 기기의 후면 카메라를 즉시 활성화할 수 있습니다. 사용자가 영수증을 카메라로 직접 촬영하여 승인(확인)하면, 촬영된 파일은 브라우저 상의 임시 파일 버퍼에 로드되고, 화면의 미리보기 영역에 축소된 이미지가 렌더링되며, 최종 가계부 저장 버튼을 누를 때 3-Tier 하이브리드 파이프라인 API로 전송되어 영수증 파싱이 수행됩니다.

**Why this priority**: 번거로운 입력 과정을 없애고 종이 영수증 사진 촬영만으로 가계부 내역 자동 생성을 시작할 수 있게 하는 핵심 킬러 기능입니다.

**Independent Test**: 모바일 기기 브라우저에서 영수증 업로드 버튼 클릭 시 OS 카메라 앱이 실행되는지 확인하고, 사진 촬영이 종료된 후 캡처된 파일이 메모리 및 화면 미리보기 영역(Image Thumbnail)에 깨짐 없이 바인딩되는지 검증합니다.

**Acceptance Scenarios**:

1. **Given** 모바일 기기에서 영수증 업로드 화면에 진입한 상태에서, **When** "영수증 촬영" 버튼을 탭하면, **Then** 모바일 OS가 제공하는 네이티브 후면 카메라 촬영 모드가 기동된다.
2. **Given** 카메라 촬영을 완료하고 사진 사용(승인)을 눌렀을 때, **When** 앱 화면으로 되돌아오면, **Then** 촬영한 영수증 이미지가 미리보기 썸네일 영역에 표시되고 파일 상태가 입력 버퍼에 바인딩된다.

### User Story 3 - Service Worker의 네트워크 상태 감지 및 사용자 피드백 제공 (Priority: P2)

사용자는 앱을 이용하는 도중 통신 기지국 전환이나 엘리베이터 진입 등으로 인해 인터넷 연결 상태가 실시간으로 변할 때, 화면 상단 또는 하단에 알림 메시지를 통해 현재 사용 가능 상태를 피드백받습니다.

**Why this priority**: 오프라인 작동이 가능하더라도 서버와의 실시간 API 통신 및 데이터 저장이 제한되는 시점을 사용자가 사전에 알 수 있게 하여 데이터 유실이나 오작동 오해를 미연에 방지합니다.

**Independent Test**: 가계부 앱 실행 상태에서 개발자 도구의 네트워크 상태를 Offline으로 토글하거나 기기의 Wi-Fi/LTE를 종료했을 때, UX 가이드라인에 명시된 토스트 메시지나 알림 배너가 스무스한 페이드인 애니메이션과 함께 표출되는지 테스트합니다.

**Acceptance Scenarios**:

1. **Given** 가계부 앱이 모바일 브라우저나 Standalone 모드로 켜져 있는 동안, **When** 네트워크가 끊겨 오프라인 상태가 되면, **Then** "현재 오프라인 상태입니다. 영수증 촬영 보관 등 오프라인 기능만 작동합니다."라는 알림 배너가 화면 상단에 HSL 다크 포인트 컬러와 함께 표시된다.

---

### Edge Cases

- **카메라 접근 권한 거부**: 사용자가 브라우저 보안 경고 창에서 카메라 접근 권한을 거부할 경우, 경고 모달을 통해 수동 파일 첨부(이미지 갤러리 또는 파일 선택창) 경로로 유연하게 복구 안내(Fallback)를 진행해야 합니다.
- **PWA 및 HTML5 Capture 미지원 환경**: 구형 단말기나 일부 특수한 인앱 브라우저(예: 일부 메신저 내장 웹뷰 등)에서 `capture` 속성을 지원하지 않는 경우, 일반 파일 탐색기 업로드창(`input type="file" accept="image/*"`)으로 자연스럽게 저하(Graceful Degradation)되어 동작해야 합니다.
- **고해상도 촬영 이미지 대용량 대응**: 모바일 카메라로 촬영된 고해상도 이미지(10MB 이상)를 그대로 전송하면 네트워크 지연 및 모바일 브라우저 크래시가 발생할 수 있으므로, HTML5 Canvas API를 이용하여 업로드 전에 가로/세로 최대 1920px 수준으로 이미지 크기를 자동 축소(Resizing) 및 압축하여 1.5MB 이하의 Blob으로 최적화한 후 백엔드에 전달해야 합니다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 PWA 규격에 부합하는 `manifest.json` 설정을 제공하여 모바일 기기 홈 화면에 웹 앱 설치가 가능하도록 관련 메타데이터(앱 이름, 시작 URL, 표시 모드: standalone, 아이콘 리스트, 테마 컬러)를 온전히 노출해야 합니다.
- **FR-002**: 시스템은 `service-worker.js` 스크립트를 클라이언트에 등록하고 활성화하여, 앱 구동에 필수적인 정적 자산(CSS, JS, 폰트, 기본 에셋 이미지)을 최초 기동 시 브라우저 캐시에 영속 보존해야 합니다.
- **FR-003**: 서비스 워커의 업데이트 라이프사이클을 통제하여, 배포 등으로 인해 서버 상의 신버전 빌드 파일이 탐지되면 사용자 화면에 "새로운 버전이 사용 가능합니다. 즉시 업데이트하시겠습니까?"라는 갱신용 사용자 선택 UI를 표시해야 합니다.
- **FR-004**: 영수증 첨부 버튼은 HTML5 Capture API 규격인 `<input type="file" accept="image/*" capture="environment">`를 활용하여 모바일 기기 후면(환경) 카메라가 디바이스 수준에서 직접 우선 호출되도록 연동되어야 합니다.
- **FR-005**: 캡처된 영수증 이미지는 업로드 전 클라이언트 브라우저 단에서 Canvas API 기반 이미지 압축을 수행하여 전송 대역폭을 최적화해야 합니다.
- **FR-006**: 프론트엔드는 전역 `navigator.onLine` 상태 및 `online`/`offline` 이벤트를 실시간으로 감지하여 네트워크 연결 변동 발생 시 화면 상에 동적 피드백을 제공해야 합니다.
- **FR-007**: 오프라인 상태에서 사용자가 영수증을 촬영하여 업로드를 시도할 경우, 시스템은 오프라인 상태에서 즉각적인 백엔드 업로드를 차단하고 화면 상의 임시 메모리 버퍼(미리보기)에만 촬영한 이미지를 유지합니다. 사용자가 브라우저를 닫거나 새로고침하면 유실될 수 있으나, 온라인 연결이 복구된 후에 사용자가 최종 저장 버튼을 누르면 동기식으로 서버에 전송되도록 설계합니다.
- **FR-008**: PWA 푸시 알림 수신 동기화 범위: 백그라운드 웹 푸시(Web Push Notification) 연동 및 푸시 서비스 구축은 이번 피처 범위에서 완전히 제외하며, PWA의 핵심 홈 화면 설치(A2HS), 오프라인 정적 리소스 캐싱, 그리고 모바일 카메라 촬영/업로드 연동에 집중합니다.

### Key Entities

- **PWA Manifest Configuration**: PWA 웹 앱의 메타데이터 정보 정의 및 설치성 제어를 위한 키-값 설정 엔티티.
- **Service Worker Cache Store**: 브라우저 로컬 저장소 내부의 Cache Storage 영역으로, 오프라인 기동을 위해 가로채어지는 정적 리소스들의 키-값 엔티티 리스트.
- **Receipt Buffer**: 카메라로부터 캡처된 이미지 파일, 크기 압축 변환을 거쳐 업로드 상태가 유효화되기까지 프론트엔드 메모리에 바인딩된 임시 데이터 엔티티.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 모바일 환경(Android Chrome, iOS Safari 등)에서 가계부 앱 최초 진입 시 설치 배너 유도 및 Manifest 파일 다운로드가 100% 정상 작동하며 개발자 도구의 Application 탭 내 PWA 검증을 에러 없이 통과합니다.
- **SC-002**: 기기의 네트워크 연결이 차단된(오프라인) 상태에서도, 이미 1회 이상 로딩된 이력이 있는 PWA 앱은 홈 화면 설치 아이콘을 클릭하여 로드될 때 3초 이내에 기본 가계부 UI 화면 프레임을 온전히 화면에 렌더링해야 합니다.
- **SC-003**: 10MB 이상의 고사양 카메라 원본 촬영 이미지가 유입되더라도, 클라이언트 측 이미지 리사이징 모듈에 의해 2초 이내에 1.5MB 이하로 용량이 축소되어 브라우저 메모리 아웃(OOM) 현상 없이 정상 업로드가 완료됩니다.
- **SC-004**: 카메라 촬영 모드로의 진입 실패 또는 권한 거부 시, 100%의 확률로 사진 보관함(갤러리) 또는 로컬 파일 업로드 모드로 안전하게 전이되며 이를 가로막는 무반응 현상이 없어야 합니다.

## Assumptions

- 사용자가 PWA 규격을 네이티브에 준하게 지원하는 표준 모던 브라우저 환경(Chrome 80+, Safari 13+, Samsung Internet 등)에서 모바일 기기를 사용하고 있다고 가정합니다.
- 오프라인 모드에서는 주로 정적 자산 로딩 및 오프라인 상태 고지, 카메라를 통한 영수증 촬영 대기까지만 로컬 단독으로 작동하며, 실제 데이터를 데이터베이스에 입력하거나 백엔드 파이프라인(OCR/LLM 파싱 등)을 가동하는 완전한 동기화는 온라인 상태가 전제되는 것으로 정의합니다.
- PWA와 카메라 캡처 API는 브라우저 보안 규정상 로컬 개발 환경(`localhost` 또는 `127.0.0.1`)이거나 상용 HTTPS SSL 보안 인증서가 온전히 배포된 암호화 네트워크 세션 하에서만 브라우저 수준에서 카메라 접근 권한 및 서비스 워커 설치를 승인하므로, 비HTTPS 네트워크에서의 차단 문제는 정상 범위의 기본 브라우저 정책 제약으로 간주합니다.
