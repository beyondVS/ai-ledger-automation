# Feature Specification: Extract PDF Text Utility

**Feature Branch**: `005-extract-pdf-text`

**Created**: 2026-05-31

**Status**: Approved

**Input**: User description: "PDF 정적 파일 내에 물리적으로 내장된 텍스트 레이어를 무손실 추출하기 위한 Python 내장 기반 PyMuPDF 혹은 pdfplumber 연동 유틸리티 클래스 코드 구현 완료."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 영수증 PDF 내장 텍스트 무손실 추출 (Priority: P1)

사용자가 시스템에 업로드한 세금계산서 또는 영수증 PDF 파일에 내장된 텍스트 레이어를 단 하나의 글자 누락이나 인코딩 깨짐 없이 완전히 추출할 수 있어야 합니다.

**Why this priority**: 이메일이나 PC로 유입되는 정형/반정형 PDF 영수증에서 텍스트를 무손실로 추출하는 것은 후속 LLM 구조화 파싱 및 가맹점 매칭 정확도를 100%에 수렴하게 만들기 위한 최우선적 디딤돌입니다.

**Independent Test**: 텍스트 레이어가 내장된 테스트용 PDF 파일을 유틸리티 클래스에 입력으로 제공하고, 추출된 텍스트가 원본 PDF에 렌더링된 텍스트 내용 및 수치 정보와 정확히 일치하는지 아웃풋 텍스트 검증을 통해 독립적으로 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 텍스트 레이어가 물리적으로 포함된 정상 영수증 PDF 파일이 준비되었을 때,
   **When** PDF 텍스트 추출 유틸리티 클래스를 호출하여 추출을 수행하면,
   **Then** PDF 내의 모든 글자(가맹점명, 사업자번호, 금액 등)가 깨짐 없이 완성형 한글 및 숫자로 누락 없이 100% 무손실 추출되어야 합니다.
2. **Given** 다단(Multi-column) 구조나 표(Table) 형태가 포함된 세금계산서 PDF 파일이 준비되었을 때,
   **When** PDF 텍스트 추출 유틸리티 클래스로 텍스트를 추출하면,
   **Then** 열(Column) 데이터가 서로 뒤섞이지 않고 인간이 읽을 수 있는 논리적 흐름 순서대로 정렬된 텍스트가 반환되어야 합니다.

---

### User Story 2 - 엔진 선택 및 자동 Fallback 처리 (Priority: P2)

PDF 파일의 내부 인코딩이나 문서 구조 특성에 따라 PyMuPDF와 pdfplumber 중 더 적합한 엔진을 선택하여 작동하고, 특정 엔진에서 인코딩 문제나 오류 발생 시 차선책 엔진으로 자동 Fallback하여 복구할 수 있어야 합니다.

**Why this priority**: PDF 포맷은 생성 도구에 따라 내부 폰트 매핑이나 인코딩 정보가 비표준인 경우가 많아 단일 라이브러리만 고집할 경우 텍스트 깨짐이나 누락이 발생하므로, 다중 엔진 상호 보완을 통해 무손실 신뢰도를 극대화해야 합니다.

**Independent Test**: 특정 라이브러리(예: PyMuPDF)에서 한글 자모가 분리되거나 텍스트 레이아웃이 깨지는 특수한 PDF 샘플을 입력하여, 시스템이 자동으로 차선 라이브러리(pdfplumber)로 전환하여 정상 추출을 완료하는지 로그와 반환된 결과의 무결성 검증을 통해 테스트합니다.

**Acceptance Scenarios**:

1. **Given** PyMuPDF 모듈에서 텍스트 파싱 오류가 발생하는 PDF 파일이 주어졌을 때,
   **When** 텍스트 추출 유틸리티 클래스를 실행하면,
   **Then** 시스템이 내부적으로 오류를 감지하고 pdfplumber 엔진으로 즉시 전환(Fallback)하여 무손실 텍스트 추출 작업을 성공적으로 마쳐야 합니다.

---

### User Story 3 - 에러 핸들링 및 유효성 검증 (Priority: P3)

암호화된 PDF 파일, 손상된 파일, 혹은 물리적 텍스트 레이어가 전혀 존재하지 않는 이미지 스캔 PDF가 입력되었을 때, 무작정 크래시를 내지 않고 명확하고 디버깅 가능한 에러 상태를 반환해야 합니다.

**Why this priority**: 비정상 파일이나 텍스트 레이어가 아예 없는 스캔 이미지 PDF가 유입되었을 때 이를 조기에 식별하고 적절한 예외를 발생시켜야, 상위 호출 모듈(비동기 Celery 작업 등)에서 무한 대기나 예기치 않은 시스템 중단을 방지하고 OCR 파이프라인으로 우회할 수 있습니다.

**Independent Test**: 암호화 비밀번호가 걸려있는 PDF 파일 또는 텍스트 레이어가 없고 단순 스캔된 이미지로만 이루어진 PDF 파일을 입력으로 주어, 사전에 약속된 커스텀 예외(예: `PDFDecryptionError`, `NoTextLayerError`)가 안전하게 발생하는지 테스트합니다.

**Acceptance Scenarios**:

1. **Given** 비밀번호로 암호화 보안 처리가 되어 읽을 수 없는 PDF 파일이 유입되었을 때,
   **When** 유틸리티 클래스를 호출하여 추출을 시도하면,
   **Then** 시스템은 프로세스 크래시 없이 즉시 이를 감지하고 적절한 암호화 관련 커스텀 예외를 발생시켜야 합니다.

---

### Edge Cases

- **초대형 PDF 파일 처리**: 50페이지가 넘는 대용량 PDF 문서가 입력되는 경우, 전체 메모리 고갈(OOM)을 예방하기 위해 페이지 단위의 제네레이터(Generator) 방식으로 텍스트를 스트리밍 추출할 수 있어야 합니다.
- **깨진 폰트 매핑(ToUnicode Table 누락)**: PDF 내부의 ToUnicode 폰트 매핑 테이블이 유실되어 추출된 텍스트가 외계어(Hex 코드 등)나 공백으로 나오는 경우, 무손실 추출 불가 상태를 감지하여 적절한 경고 또는 대체 처리를 안내해야 합니다.
- **빈 문서(Blank Document)**: 파일 크기는 존재하나 내부에 페이지 정보나 객체가 아무것도 없는 빈 PDF 파일이 입력되는 경우에 대한 안정적 예외 처리가 필요합니다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 입력받은 PDF 파일 경로 또는 바이트 스트림(Byte Stream) 객체로부터 PDF 문서를 안전하게 로드할 수 있어야 합니다.
- **FR-002**: 시스템은 `PyMuPDF`와 `pdfplumber` 라이브러리를 동적으로 활용하는 독립적인 텍스트 추출 어댑터 엔진 구조를 포함해야 합니다.
- **FR-003**: 시스템은 기본적으로 성능이 뛰어난 `PyMuPDF` 엔진을 최우선(Primary)으로 작동하여 텍스트를 추출하되, 추출 중 물리적 인코딩 예외가 발생하거나 한글 깨짐 및 자모 분리가 의심되는 비표준 인코딩의 경우 자동으로 `pdfplumber` 엔진으로 전환하여 무손실 추출을 완수하는 Fallback 메커니즘을 내장해야 합니다.
- **FR-004**: 시스템은 텍스트 추출 시, 텍스트가 일렬로 나열되는 '단순 텍스트 추출 모드(Raw Mode)'와 탭 및 공백 문자를 보존하여 표와 컬럼 등의 시각적 격자 구조를 최대한 유지하는 '레이아웃 보존 추출 모드(Layout-Preserved Mode)'를 매개변수 플래그(`layout: bool`)를 통해 제어 및 전환 가능해야 하며, 기본값은 레이아웃 보존 모드로 구성합니다.
- **FR-005**: 암호화로 인해 접근이 거부된 PDF 문서이거나, 물리적 텍스트 레이어가 존재하지 않는 스캔 이미지 PDF 등의 비정상 파일이 유입되는 경우, 강제 프로세스 크래시나 무한 대기를 차단하기 위해 실패 사유와 예외 상세 상태가 매핑된 구조화된 에러 DTO(`ExtractionResult`에서 `success: False`, `error_message: "..."`)를 안전하고 디버깅 가능하게 반환해야 합니다.
- **FR-006**: 시스템은 추출된 한글 텍스트에 대해 NFC(Normal Form Canonical Composition) 유니코드 표준 정규화를 자동 적용하여, 초성/중성/종성이 분리되는 현상(예: 'ㄱ-ㅏ-ㄱ-ㅏ-ㅇ-ㅔ-ㅂ-ㅜ')을 완벽히 방지해야 합니다.
- **FR-007**: 시스템은 대용량 PDF 처리를 위해 페이지 범위를 명시적으로 지정하여 부분 추출(Selective Extraction)할 수 있는 인터페이스를 제공해야 합니다.

### Key Entities *(include if feature involves data)*

- **PDFTextExtractor**: PDF 텍스트 무손실 추출을 총괄하는 메인 유틸리티 인터페이스 클래스입니다.
  - *주요 속성*: `file_source` (경로 혹은 바이트 데이터), `engine_preference` (선호 엔진 설정), `normalize_unicode` (한글 정규화 여부 플래그)
- **ExtractionResult**: 추출 완료 후 호출자에게 전달되는 최종 데이터 전송 객체(DTO)입니다.
  - *주요 속성*: `raw_text` (전체 페이지 합산 추출 텍스트), `page_texts` (페이지별 텍스트 매핑 딕셔너리), `success` (성공 여부 불리언), `extracted_pages` (추출 성공한 페이지 수), `used_engine` (추출에 사용된 라이브러리 명칭), `error_message` (실패 시 에러 메시지)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 텍스트 레이어가 정상적으로 내장된 100개의 샘플 PDF(영수증 및 세금계산서)에 대해 텍스트 데이터 캐릭터(Character) 누락률이 0%를 유지해야 합니다.
- **SC-002**: 평균 2페이지 분량의 영수증 PDF 파일에 대한 텍스트 추출 시간이 단일 스레드 기준 0.3초 미만으로 완료되어야 합니다.
- **SC-003**: 추출된 모든 한글 문자열에서 자모 분리 현상이 발생하지 않고 완전히 복원된 완성형 한글 조합 비율이 100%여야 합니다.
- **SC-004**: 유효하지 않거나 암호화된 PDF 입력 시, 크래시(Segmentation Fault 등)를 방지하고 100% 사전에 약속된 안전한 에러 응답 객체(ExtractionResult) 혹은 커스텀 예외를 반환해야 합니다.

## Assumptions

- **A-001**: 업로드되거나 처리 대상이 되는 PDF 파일은 OCR 분석이 요구되는 "스캔된 이미지 전용 PDF"가 아니라, 원본 생성 시점부터 텍스트 메타데이터 레이어가 물리적으로 포함된 PDF 파일임을 가정합니다. (OCR 모듈은 본 유틸리티의 핵심 범위에서 배제)
- **A-002**: 프로젝트 내 가상환경(`uv` 환경)에 `PyMuPDF`와 `pdfplumber` 패키지가 의존성 락파일 기준으로 올바르게 기기 내에 설치 및 가용한 상태임을 가정합니다.
- **A-003**: PDF 파일 로드 시의 파일 시스템 읽기 권한 및 원격지 다운로드 파일의 임시 적재 디렉토리 접근 권한이 사전에 확보되어 있다고 가정합니다.
- **A-004**: 다국어 지원의 경우 한국어와 영어, 숫자를 핵심 타겟으로 삼으며, 특수 유니코드 기호(이모티콘 등)나 복잡한 수학 공식 렌더링 폰트는 고려하지 않습니다.
