# Feature Specification: 비동기 워커 알림 소비 태스크 오프라인 수신 단말 E2E 모바일 푸시 알림 도달 및 디바이스 캐싱 데이터 무결 테스트 완료

**Feature Branch**: `027-e2e-offline-push-caching`

**Created**: 2026-06-21

**Status**: Draft

**Input**: User description: "비동기 워커 알림 소비 태스크 오프라인 수신 단말 E2E 모바일 푸시 알림 도달 및 디바이스 캐싱 데이터 무결 테스트 완료."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 오프라인 단말의 웹 푸시 알림 지연 도달 검증 (Priority: P1)

단말이 네트워크 연결이 유실된 오프라인 상태일 때, 백엔드 비동기 워커가 푸시 알림을 성공적으로 발송하여 외부 브라우저 푸시 서버(FCM/APNs)에 안전하게 대기 적재되며, 이후 단말이 다시 온라인 상태로 복귀했을 때 누락 없이 지연된 알림이 도달하여 최종 사용자 화면에 노출되어야 한다.

**Why this priority**: 모바일 사용자는 터널 통과, 비행기 모드, 지하철 내 일시 음영 지역 등 수많은 오프라인 상황을 겪는다. 네트워크 복귀 시 알림이 안전하게 유실 없이 지연 도달하는 흐름을 검증하는 것은 이 푸시 알림 서비스의 신뢰성을 담보하는 가장 기본적인 핵심 가치이다.

**Independent Test**:
1. 사용자가 단말의 비행기 모드를 활성화하거나 개발자 도구에서 네트워크를 오프라인 상태로 설정한다.
2. 백엔드에서 비동기 Celery 태스크를 통해 특정 사용자에게 알림을 발송한다.
3. 백엔드 로그 상에서 외부 푸시 서버(FCM/APNs)로의 전송 시도가 성공했음을 확인한다.
4. 사용자가 단말의 네트워크 연결을 복구(온라인 상태로 전환)한다.
5. 단말에 푸시 알림이 정상적으로 수신되어 팝업/배너 형식으로 화면에 노출됨을 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 웹 앱에 로그인되어 있고 푸시 알림 권한을 허용했으며 단말이 오프라인 상태일 때, **When** 백엔드 비동기 워커가 푸시 알림 발송 태스크를 수행하여 외부 푸시 중개 서버에 적재를 마쳤을 때, **Then** 단말이 온라인으로 전환된 지 5초 이내에 해당 푸시 알림이 단말에 도달하여 사용자에게 노출된다.
2. **Given** 단말이 오프라인 상태일 때 다수의 푸시 알림(예: 3개)이 연속으로 발송되었을 때, **When** 단말이 온라인으로 전환될 때, **Then** 모든 알림이 유실되지 않고 발송 순서대로 단말에 순차적으로 도달하여 화면에 노출된다.

### User Story 2 - 수신 알림의 디바이스 로컬 캐싱 및 백엔드 로그 무결성 대조 검증 (Priority: P2)

단말에 수신되어 화면에 노출된 푸시 알림 메시지는 서비스 워커에 의해 백그라운드 환경에서 가로채어져 디바이스 로컬 영속 캐시(IndexedDB 등)에 즉시 저장되어야 하며, 로컬에 저장된 알림의 메타데이터와 백엔드의 `NotificationLog` 데이터베이스 레코드가 100% 동일한 정합성을 유지하고 있는지 비교 검증되어야 한다.

**Why this priority**: 사용자가 푸시 팝업을 탭하여 열거나, 앱 내의 알림 보관함 리스트를 오프라인 환경에서도 안전하게 조회할 수 있도록 로컬 스토리지에 무결하게 캐싱하는 로직이 필수적이다. 캐시된 정보의 필드가 백엔드 서버와 불일치하거나 깨지는 현상을 미연에 검증하여 데이터 무결성을 보장해야 한다.

**Independent Test**:
1. 온라인 단말에서 알림을 정상 수신한다.
2. 브라우저 개발자 도구의 Application Storage 탭을 활성화하여 로컬 IndexedDB에 해당 알림에 대한 key, title, body, status, timestamp 필드가 정확히 매핑되어 생성되었는지 확인한다.
3. 백엔드 API를 통해 반환되는 해당 알림 데이터와 로컬 IndexedDB 레코드를 1대1 필드 대조하여 불일치 항목이 전혀 존재하지 않음을 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 웹 푸시 알림을 정상 수신했을 때, **When** 서비스 워커가 백그라운드에서 푸시 이벤트를 핸들링할 때, **Then** 사용자 개입 없이 로컬 IndexedDB에 수신된 알림의 모든 필수 정보가 유실 없이 즉시 동기화 적재된다.
2. **Given** 수신 및 캐싱이 완료된 상태에서, **When** 디바이스 캐시 내용과 백엔드 `NotificationLog` 테이블을 동일 알림 ID를 기준으로 대조할 때, **Then** 알림 제목(title), 내용(body), 전송시각(timestamp) 등 핵심 필드의 데이터 바이트 수준 정합성이 100% 일치한다.

### User Story 3 - 네트워크 플래핑 시의 중복 캐싱 방지 및 자동 재동기화 검증 (Priority: P3)

네트워크 연결이 끊겼다 붙었다를 반복하는 불안정한 네트워크 전환 환경(플래핑 현상)에서 동일한 알림이 중복하여 단말에 노출되거나 디바이스 로컬 캐시에 중복 레코드로 오염 적재되는 것을 사전 방지하고, 최종 정합성을 자동 복구하여 무결성을 유지해야 한다.

**Why this priority**: 모바일 사용자는 엘리베이터나 터널을 이용할 때 빈번히 단절과 재연결을 반복한다. 이 과정에서 브라우저 푸시 서버와 단말 간의 Acknowledgment 실패로 인해 동일 메시지가 중복 수신되어 화면을 도배하거나 캐시 내역을 지저분하게 만드는 중복 버그를 원천 차단하여 UX를 수호해야 한다.

**Independent Test**:
1. 백엔드에서 특정 알림 발송 태스크를 대기시킨 상태에서 단말의 네트워크 차단 및 연결을 3회 이상 단시간에 반복 수행한다.
2. 해당 과정에서 발송된 알림이 단말에 도달했을 때 중복 팝업이 노출되지 않는지 확인한다.
3. 로컬 캐시(IndexedDB)를 확인하여 고유 식별자(ID) 기준으로 중복 생성된 레코드가 존재하지 않고 단 1개의 무결한 레코드만 남아있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 동일 알림 ID를 가진 푸시 알림이 네트워크 재연결 시점에 다중 발송/수신되는 비정상 흐름이 발생할 때, **When** 서비스 워커가 로컬 캐시에 쓰기를 수행할 때, **Then** 멱등성 식별 키에 의해 중복 처리가 차단되어 IndexedDB 상에는 단 하나의 레코드만 유니크하게 보존된다.

---

### Edge Cases

- **FCM/APNs TTL 만료**: 단말이 매우 오랫동안(예: 4주 이상) 오프라인 상태를 유지하여 웹 푸시 중개 서버 내의 메시지 보존 기한(TTL)이 만료된 경우, 네트워크 연결이 복구되었을 때 푸시 수신을 생략하더라도 온라인 복귀 즉시 백엔드 동기화 API를 통해 최신 미도달 알림 내역을 로컬 캐시에 벌크로 일치 동기화할 수 있어야 한다.
- **스토리지 쿼터 초과 및 인코그니토 모드**: 브라우저의 IndexedDB 저장 한도가 가득 찼거나, 시크릿 브라우징(인코그니토) 상태여서 IndexedDB 사용이 차단된 경우, 시스템은 에러로 중단되지 않고 인메모리 캐시(Session Storage 등)로 자동 격리 전환되어 제한된 무결성을 유지하고 사용자에게 경고 메시지를 로그에 기록해야 한다.
- **알림 수신 권한 번복**: 백그라운드 수신 과정 도중 사용자가 브라우저 설정에서 푸시 알림 수신 권한을 즉각 거부했을 때, 서비스 워커의 백그라운드 캐싱 프로세스가 예외 처리 코드에 의해 에러를 방지하고 정상 종료되어야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자의 단말이 오프라인 상태일 때 백엔드 비동기 워커에 의해 발송된 푸시 알림을 외부 푸시 서비스(FCM/APNs)의 전송 큐에 정상적으로 안전 위임 적재해야 한다.
- **FR-002**: 단말이 다시 온라인 상태로 복귀했을 때, 외부 푸시 서비스의 큐에 저장되어 있던 지연 푸시 메시지를 누락 없이 단말의 서비스 워커(Service Worker)가 즉시(또는 네트워크 복구 즉시) 최종 수신해야 한다.
- **FR-003**: 서비스 워커는 수신한 모든 푸시 알림 메시지를 화면에 노출하는 동시에, 디바이스 로컬 영속 스토리지(IndexedDB)의 알림 보관함 테이블에 자동 적재(디바이스 캐싱)해야 한다.
- **FR-004**: 시스템은 디바이스 캐시에 적재되는 정보가 백엔드 `NotificationLog`의 PK(UUIDv7)와 100% 매핑되도록 보장하여, 고유 ID 기반으로 로컬 캐시의 중복 생성을 원천 차단하는 멱등성 검사를 필수로 수행해야 한다.
- **FR-005**: 단말이 푸시를 수신하여 로컬 캐시에 무결하게 적재를 완료했을 때, 서비스 워커는 백엔드 수신 확인(Acknowledgment) API를 호출하여 백엔드 DB 내의 알림 발송 상태를 '단말 도달(DELIVERED)' 및 '수신 완료'로 최종 갱신해야 한다.
- **FR-006**: 시스템은 기기 자원 보호 및 백엔드 데이터 라이프사이클과의 일관성을 위해 단말 IndexedDB 로컬 캐시에 최근 30일 이내에 수신된 최신 100개의 알림 레코드만 보존해야 하며, 기준을 초과하는 오래된 알림은 자동으로 로컬 저장소에서 퍼지(Purge) 제거해야 한다.
- **FR-007**: 시스템은 타 기기에서의 읽음 상태 번복 등 백엔드 데이터와 단말 로컬 캐시 간의 정합성 불일치를 실시간 보정하기 위해, 사용자가 앱을 포그라운드로 활성화(Document Focus 진입)할 때 동기화 API를 즉시 1회 호출하여 로컬 캐시 상태를 서버 상태에 맞게 일괄 갱신해야 한다.
- **FR-008**: 시스템은 네트워크 오프라인 조건 및 서비스 워커의 백그라운드 캐싱 정합성을 기계적으로 상시 증명하기 위해, Playwright의 네트워크 에뮬레이션(`context.setOffline(true)`) 및 Mock Push Service를 연동한 E2E 자동화 통합 테스트 코드를 구축하고 CI 빌드 검증 파이프라인에 영구 통합해야 한다.

### Key Entities *(include if feature involves data)*

- **CachedNotification**: 디바이스 로컬 영속 저장소(IndexedDB) 내에 캐싱되어 보관되는 개별 알림 엔티티.
  - *Attributes*: `id` (UUIDv7, Primary Key 및 백엔드 ID 대조용), `title` (텍스트), `body` (텍스트), `status` (READ / UNREAD / ARCHIVED), `created_at` (타임스탬프, ISO 8601 UTC), `synced_at` (로컬 동기화 완료 시각)
- **NotificationLog (기존 연계)**: 백엔드 데이터베이스 상에 기록되는 개별 알림의 고유 트랙킹 엔티티.
  - *Attributes*: `id` (UUIDv7), `user_id` (사용자 식별 외래키), `type` (알림 유형), `payload` (JSONB 데이터), `status` (PENDING / SENT / DELIVERED / FAILED), `created_at` (생성시각), `updated_at` (갱신시각)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 10분 이상 네트워크가 차단된 오프라인 단말이 온라인으로 전환된 시점부터 5초 이내에 브라우저 푸시 서비스(FCM/APNs)에 대기 중이던 지연 푸시 알림이 E2E로 서비스 워커에 무사히 도달해야 한다.
- **SC-002**: 도달한 푸시 알림은 서비스 워커 핸들러 작동 즉시 누락 없이 100% 로컬 영속 저장소(IndexedDB)에 디바이스 캐싱 처리가 완수되어야 한다.
- **SC-003**: 1,000건의 비동기 푸시 발송 및 수신 무결 테스트를 임의의 오프라인 시나리오를 섞어 진행했을 때, 백엔드 데이터베이스의 `DELIVERED` 로그 상태와 디바이스 로컬 캐시의 적재 레코드 간 불일치 및 누락 비율이 0%를 달성해야 한다.
- **SC-004**: 수동 캐시 강제 동기화 트리거 작동 시, 전체 동기화 및 렌더링 완료까지 소요되는 사용자 체감 응답 속도는 1.5초 이내여야 한다.

## Assumptions

- 사용자가 웹 앱에 진입하여 푸시 권한 요청 창에 승인(Granted)을 정상적으로 마친 상태이다.
- 외부 푸시 중개 서비스(FCM/APNs)의 메시지 보존 기간(TTL)은 최소 24시간 이상으로 설정되어 있어, 일시적인 오프라인 단말(24시간 이내)에 보낼 메시지가 중개자 선에서 조기 증발하지 않는다.
- 서비스 워커가 백그라운드 환경에서도 푸시 이벤트를 온전히 수신하여 IndexedDB를 사용할 수 있는 최신 모바일/웹 브라우저 보안 규격을 전적으로 신뢰한다.
- 다중 단말 로그인(예: 동일 계정으로 스마트폰, 태블릿, PC 동시 사용) 환경에서의 단말 간 실시간 동기화 정합성은 본 E2E 무결성 검증 MVP 범위에서 제외하며, 단일 단말 디바이스 기준 E2E 무결성 입증에 전념한다.
